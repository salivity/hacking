Overlapping IP Fragmentation Firewall Evasion

This article examines how threat actors exploit overlapping IP fragmentation to bypass packet filters and network intrusion detection systems (NIDS). By manipulating IP header fields such as the Fragment Offset and More Fragments (MF) flags, attackers create intentionally misaligned and conflicting packet fragments. Because packet filters and destination operating systems often use different rules to reassemble overlapping data, attackers can mask malicious payloads during transit, allowing malicious traffic to slip past defenses and execute on the target host.

Understanding IP Fragmentation

The Internet Protocol (IP) allows packets to be split into smaller units, called fragments, when transmitting data across networks with a Maximum Transmission Unit (MTU) smaller than the packet size. Reassembly occurs at the destination host using three key fields from the IP header:

  • Identification (ID): A unique 16-bit value identifying fragments originating from the same original packet.
  • Flags: Includes the "More Fragments" (MF) flag, which indicates whether more fragments follow (MF=1) or if it is the final segment (MF=0).
  • Fragment Offset: A 13-bit value measuring the relative position of the fragment data within the original IP datagram, calculated in 8-byte blocks.

Standard networking assumes fragments arrive sequentially or out of order without duplicate offsets. However, attackers intentionally craft packets with overlapping offsets to exploit how intermediate security devices process them versus the target host.

Key Overlapping Fragmentation Techniques

1. Tiny Fragment Attack

In a tiny fragment attack, the attacker forces the first fragment to be extremely small—often just large enough to hold the IP header and a fraction of the Layer 4 (TCP/UDP) header.

Traditional stateless packet filters typically evaluate access control rules (such as blocking access to a sensitive port like SSH or RDP) against the first fragment containing offset zero (Offset = 0). If the Layer 4 destination port is pushed into the second fragment (Offset > 0), the firewall cannot see the port number in the first fragment and may allow it through based on default permit rules. Subsequent fragments lack the Layer 4 header altogether and are routinely forwarded, allowing the target host to reconstruct the unauthorized connection.

2. Overlapping Fragment Overwrite

In an overlapping fragment attack, an attacker sends an initial fragment containing seemingly benign data to satisfy the firewall's inspection engine, followed by a subsequent fragment whose offset overlaps the data of the first fragment.

  • Header Overwrite: The initial fragment arrives with an authorized destination port (e.g., port 80 for HTTP). A subsequent fragment arrives with an offset that overwrites the destination port in the host's reassembly buffer with a restricted port (e.g., port 445 for SMB). The packet filter permits both fragments, but the receiving host connects to the restricted service.
  • Payload Overwrite: The initial fragment contains benign application-layer data that passes an intrusion detection signature check. The overlapping fragment overwrites portions of that benign payload with shellcode or exploit commands during host-level reassembly.

3. Exploiting OS Reassembly Divergence (Insertion vs. Evasion)

Firewall evasion through overlapping fragments relies primarily on the differences in how operating systems resolve conflicting data. When two fragments claim the same offset, an operating system must choose whether to favor the original data (First) or the new data (Last).

Common reassembly policies include:

  • First Policy (e.g., BSD, Cisco IOS): The host keeps the original data from the earlier fragment and discards the overlapping bytes of subsequent fragments.
  • Last Policy (e.g., Windows): The host overwrites the original data with the bytes provided in the newer fragment.
  • Linux Policy: Linux systems employ hybrid heuristics that favor the original fragment in some offset conditions and newer fragments in others, depending on the kernel version and specific packet boundaries.

If a firewall uses a "First" policy to inspect traffic, an attacker targeting a Windows host will design the attack so that the benign data is in the first fragment and the malicious code is in the overlapping second fragment. The firewall inspects and permits the initial data, while the target host overwrites the data with the malicious payload. Conversely, if the firewall uses a "Last" policy and the target is a BSD system, the attacker reverses the order of the payload delivery to achieve evasion.

Defenses Against Fragmentation Evasion

  • Traffic Normalization: Modern firewalls and intrusion prevention systems (IPS) use packet normalization (scrubbing) to defragment packets, resolve overlaps uniformly, and re-fragment or forward the stream in a clean, unambiguous state.
  • Drop Overlapping Packets: Modern network devices can be configured to drop any packet where Offset + Fragment Length creates a collision with an existing fragment in the queue, as legitimate IP stacks rarely produce overlapping fragments under normal network conditions.
  • Minimum Fragment Size Enforcement: Enforcing a minimum fragment size rule ensures that the entire Layer 4 header is always present in the first fragment (Offset = 0), neutralizing tiny fragment attacks.
