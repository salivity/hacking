Dan Kaminsky DNS Cache Poisoning Flaws Explained

In 2008, security researcher Dan Kaminsky uncovered a fundamental structural vulnerability in the Domain Name System (DNS) that exposed the entire internet to widespread cache poisoning attacks. By exploiting predictable transaction identifiers and the protocol's lightweight verification model, the attack allowed adversaries to reliably inject forged DNS records into recursive resolvers, rerouting web traffic, intercepting emails, and undermining encrypted communications. Understanding this vulnerability requires examining the original design constraints of DNS, particularly its reliance on insufficient entropy and its handling of delegated authority records.

The Limits of 16-Bit Transaction IDs

The core mechanism of DNS relies on UDP, a stateless protocol that prioritizes speed over session verification. When a recursive resolver queries an authoritative nameserver on behalf of a client, it generates a 16-bit Transaction ID (TXID). This number is included in the query header, and the authoritative server must reflect the exact same TXID in its response for the answer to be accepted.

Because the TXID is only 16 bits wide, there are just 65,536 possible identifier values. Under traditional DNS poisoning approaches, an attacker had to race an authoritative server to guess the TXID for a requested domain, such as example.com. If the attacker failed and the legitimate response arrived first, the resolver cached the genuine record for the duration specified by the Time to Live (TTL). The attacker then had to wait hours or days for the TTL to expire before attempting another guess, making practical exploitation mathematically improbable against responsive authoritative servers.

Static Source Ports and Low Entropy

The structural flaw in DNS was magnified by the widespread practice of querying from a fixed UDP source port. Early DNS implementations defaulted to using UDP port 53 not just to listen for incoming queries, but also as the source port for outbound requests.

This architectural design choice meant that an attacker did not need to guess both the port and the TXID. With the source IP, destination IP, source port (53), and destination port (53) effectively fixed and known, the 16-bit TXID was the sole layer of defense guarding the transaction against spoofing.

The Nonce Elimination Bypass: Non-Existent Subdomains

Kaminsky’s key breakthrough resolved the TTL waiting constraint by altering the query target. Instead of repeatedly requesting example.com, an attacker queried the target resolver for non-existent, randomly generated subdomains, such as 1.example.com, 2.example.com, or 3.example.com.

Because these subdomains had never been queried before, they were not cached, prompting the resolver to issue a fresh outbound query to the authoritative nameserver every single time. Concurrently, the attacker flooded the resolver with hundreds of forged responses for each bogus subdomain. By issuing thousands of requests for unique subdomains in rapid succession, the attacker could brute-force the 65,536 possible TXID values within seconds without ever triggering a negative cache block on the primary target.

Authority Section Exploitation

Generating a cache entry for a non-existent subdomain does not inherently compromise a domain. The critical structural vulnerability lay in how DNS resolvers processed the "Authority" and "Additional" sections of a DNS response.

When the attacker’s forged response finally matched the 16-bit TXID of an outstanding query (e.g., 5842.example.com), the response did not merely provide an answer for that subdomain. It also contained an authoritative nameserver delegation in the Authority section, asserting that a malicious nameserver was the new authority for the entire parent domain (example.com). The resolver, validating the payload against the matched TXID, accepted the Authority delegation as valid glue data and overwrote its existing records for the domain's root authoritative servers.

Once poisoned, every subsequent user query for any host under example.com was directed to the attacker's infrastructure.

Resolution and Modern Defenses

The Kaminsky vulnerability exposed that DNS, as designed in RFC 1034 and RFC 1035, fundamentally lacked cryptographic authentication. As an immediate mitigation, the internet engineering community coordinated to implement source port randomization (SPR). By randomizing the UDP source port across the ephemeral port range (~16 extra bits of entropy) alongside the 16-bit TXID, the total search space increased from 65,536 combinations to over 2 billion, rendering brute-force attacks impractical. The long-term architectural resolution remains DNS Security Extensions (DNSSEC), which uses public-key cryptography to cryptographically validate the authenticity and integrity of DNS responses.
