PPPoE Intermediate Agent Spoofing Vulnerabilities

Point-to-Point Protocol over Ethernet (PPPoE) is widely deployed by broadband Internet Service Providers (ISPs) to manage subscriber authentication, session establishment, and billing across access networks. However, architectural reliance on unauthenticated Layer 2 metadata allows adversaries to exploit the PPPoE Intermediate Agent (PPPoE IA) mechanism. This article outlines how the PPPoE Discovery phase operates, the specific protocol and configuration vulnerabilities that permit Intermediate Agent spoofing, the attack vectors used against broadband providers, and the engineering controls required to mitigate the risk.

The Role of the PPPoE Intermediate Agent

In standard broadband architectures, such as those defined by Broadband Forum TR-101, an access node—such as an Optical Line Terminal (OLT), DSLAM, or aggregation switch—sits between the customer premises equipment (CPE) and the Broadband Network Gateway (BNG) or Broadband Remote Access Server (BRAS).

Because the BNG needs to identify the physical subscriber line for authentication, service-tier allocation, and regulatory compliance (lawful intercept), the access node acts as a PPPoE Intermediate Agent. During the PPPoE Active Discovery (PPPoE-AD) phase, the Intermediate Agent intercepts subscriber broadcast frames (PADI - Active Discovery Initiation and PADR - Active Discovery Request) and appends a Vendor-Specific Tag (Tag type 0x0105). This tag encapsulates crucial metadata, primarily:

  • Circuit-ID: Identifies the physical rack, frame, slot, and port of the access node.
  • Remote-ID: Often maps to a customer account number, subscriber ID, or unique modem identifier.

The BNG parses these tags and forwards them via RADIUS/Diameter attributes (such as Vendor-Specific Attributes / NAS-Port-Id) to the Authentication, Authorization, and Accounting (AAA) server.

Core Vulnerabilities Permitting Intermediate Agent Spoofing

Intermediate Agent spoofing occurs when an attacker injects or alters these Vendor-Specific Tags to bypass access controls, hijack accounts, or manipulate traffic routing. Several protocol-level and implementation flaws make this possible.

1. Absence of Cryptographic Integrity in PPPoE Discovery

The PPPoE standard (RFC 2516) and TR-101 specifications contain no native cryptographic authentication or message integrity checks for discovery frames. PPPoE Active Discovery packets traverse the network as cleartext Layer 2 Ethernet payloads (EtherType 0x8863). Because tags are not digitally signed, a BNG has no inherent cryptographic mechanism to verify whether a Vendor-Specific Tag originated from a legitimate intermediate switch or directly from an end-user device.

2. Implicit Trust and Inadequate Tag Stripping on Customer Ports

The most common implementation flaw is the failure of access nodes to enforce strict trust boundaries. By default, a secure Intermediate Agent must inspect incoming frames on untrusted (customer-facing) interfaces:

  • If an incoming PADI or PADR packet already contains a Vendor-Specific Tag (0x0105), the switch must drop the packet or strip the pre-existing tag before appending its own.
  • When access switches fail to strip these tags, they pass the user-crafted tag directly to the BNG, or they append an additional tag, leading to parsing ambiguities on the BNG where the first (spoofed) tag takes precedence.

3. Permissive Layer 2 Environments and Lack of Port Isolation

In broadband networks with flat Layer 2 aggregation networks or misconfigured VLAN architectures, customer ports are not always isolated from one another. Without Private VLANs (PVLANs) or Split-Horizon forwarding, a compromised subscriber can see or inject Layer 2 frames into the shared broadcast domain. This allows the injection of crafted PADO (Active Discovery Offer) or PADS (Active Discovery Session-confirmation) packets directly into other subscribers' sessions.

4. BNG Credential Decoupling

Many broadband architectures rely heavily on "Option 82-style" circuit authorization, where authentication is tied primarily to the Circuit-ID/Remote-ID rather than strong, per-subscriber PPPoE credentials (often using blank or static PAP/CHAP passwords). When the BNG relies exclusively on the physical identifiers supplied in the intermediate tag, spoofing that tag guarantees immediate identity impersonation.

Exploitation Scenarios in Provider Networks

When attackers successfully manipulate PPPoE IA tags, several high-impact attack vectors emerge:

  • Subscription Theft and Tier Bypassing: An attacker on a lower-tier plan crafts a PADI frame containing the Circuit-ID of an enterprise-tier subscriber on the same aggregation loop. If the access switch does not drop incoming client tags, the BNG allocates higher bandwidth, static public IP blocks, or unmetered transit to the attacker.
  • Session Hijacking and Redirection: By injecting spoofed PPPoE discovery responses or forcing renegotiations, an attacker can manipulate MAC-to-circuit bindings on the BNG, redirecting inbound traffic meant for legitimate subscribers through an attacker-controlled endpoint.
  • Bypassing Lawful Interception and Logging: By masquerading as another line identifier, an attacker ensures that any malicious traffic logged at the ISP's core networks points directly to an innocent subscriber's physical port.
  • Denial of Service (DoS): Injecting malformed tags or flooding the BNG with conflicting Circuit-IDs can exhaust the state machine of the Intermediate Agent or trigger session disconnects for legitimate users due to duplicate circuit bindings.

Mitigation Strategies

Securing the PPPoE access architecture requires defense-in-depth across the access nodes, aggregation layers, and BNGs:

  1. Enforce Interface Trust States: Configure access switches and DSLAMs/OLTs with explicit port trust models. Customer-facing user-to-network interfaces (UNIs) must be marked as untrusted, and any incoming frame bearing a pre-existing PPPoE Intermediate Agent tag (0x0105) must be dropped immediately.
  2. Strict Layer 2 Isolation: Deploy Private VLANs (PVLANs) or Port Isolation on all access equipment to ensure customer endpoints can communicate strictly with the upstream gateway and never with peer subscribers.
  3. Strong Credential Binding: Avoid zero-touch or line-only authentication. The AAA infrastructure should cross-validate PPPoE PAP/CHAP credentials against the incoming Circuit-ID and the originating MAC address, rejecting sessions where credentials do not match the expected physical circuit profile.
  4. Tag Overwrite Policies: Configure intermediate agents to enforce an "overwrite" or "strip" policy rather than an "append" policy for incoming tags, ensuring that the switch's locally generated hardware parameters replace any payload injected by the client.
