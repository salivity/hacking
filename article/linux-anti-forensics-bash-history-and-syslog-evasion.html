Linux Anti-Forensics: Bash History and Syslog Evasion

This article examines the primary techniques adversaries employ to hide their operational footprint on Linux systems by evading or erasing interactive Bash command history and disabling system logging facilities such as syslog. Understanding these anti-forensic mechanisms is critical for systems administrators, incident responders, and security analysts aiming to detect unauthorized access, preserve evidentiary integrity, and harden auditing mechanisms against administrative tampering.

Manipulating Interactive Bash History

When an interactive shell session terminates, Bash typically flushes commands executed during the session from memory to an on-disk history file (usually located at ~/.bash_history). Intruders employ several runtime techniques to alter this behavior:

  • Modifying Environment Variables: Bash relies on specific variables to manage logging behavior. By unsetting the history file pointer (unset HISTFILE) or setting the history buffer sizes to zero (export HISTSIZE=0 and export HISTFILESIZE=0), the shell ceases recording executed commands both in memory and to the persistent file.
  • Toggling Shell Options: The command set +o history disables history collection for the active session entirely. Conversely, set -o history re-enables it, allowing selective exclusion of sensitive activity while leaving innocuous commands recorded.
  • Bypassing via Space Prefixes: If the shell configuration utilizes HISTCONTROL=ignorespace or HISTCONTROL=ignoreboth, prepending a whitespace character to any command prevents it from being appended to the internal history list.
  • Targeting History Files Directly: Intruders may overwrite or link the history storage to discard output automatically. Linking the file to /dev/null (ln -sf /dev/null ~/.bash_history) causes subsequent writes to be discarded. In other cases, files are truncated using > ~/.bash_history or wiped using utilities like shred before session termination.
  • Spawning Non-Logging Shells: Executing commands inside subshells configured without resource files (e.g., bash --norc) or using specialized interactive wrappers (such as Python's pty.spawn) can prevent default profile scripts from initializing persistent history mechanisms.

Disabling and Tampering with Syslog Facilities

System-wide authentication, privilege escalation, and runtime events are typically captured by logging daemons such as rsyslog, syslog-ng, or systemd-journald. When administrative or root access is achieved, unauthorized users often target these services to suppress event generation:

  • Service Termination and Masking: Using service managers, intruders can halt logging daemons directly via commands like systemctl stop rsyslog or service rsyslog stop. To prevent automatic recovery or restart by watchdog processes, the services may be masked (systemctl mask rsyslog), binding the service unit to /dev/null.
  • Disabling the Linux Audit Framework: The Linux Auditing System (auditd) logs detailed operational metrics directly from the kernel. Threat actors with root privileges can disable this kernel subsystem dynamically by executing auditctl -e 0, blinding kernel-level tracking of system calls and file integrity monitoring.
  • Altering Logging Configurations: Rather than stopping daemons—which can trigger alerts in enterprise monitoring solutions—configurations may be subtly modified. For example, editing /etc/rsyslog.conf or configuration snippets in /etc/rsyslog.d/ to filter out specific facilities (such as auth or authpriv) directs sensitive events to /dev/null. Similarly, configuring Storage=none in /etc/systemd/journald.conf stops journald from writing logs to non-volatile memory.
  • Direct Truncation of Log Files: To avoid file-deletion alerts triggered by log rotation or monitoring tools, intruders frequently truncate active files in /var/log/ (e.g., auth.log, secure, syslog) using utilities such as truncate -s 0 /var/log/auth.log or shell redirection (> /var/log/secure), setting file sizes to zero bytes while keeping open file descriptors intact.
