How Invalid Curve Attacks Extract Private Keys

An invalid curve attack is an exploit targeting Elliptic Curve Cryptography (ECC) protocols—most notably Elliptic Curve Diffie-Hellman (ECDH)—that allows an adversary to fully recover a victim's private key. The attack exploits a critical implementation vulnerability where a cryptographic system accepts and performs scalar multiplication on an arbitrary point supplied by an external party without verifying that the point actually lies on the designated elliptic curve. By forcing calculations on mathematically weaker curves with small subgroup orders, attackers can solve the discrete logarithm problem in fragments and reconstruct the complete private key using the Chinese Remainder Theorem.

The Missing Equation Check: Independence from the Parameter \(b\)

In standard ECC over a prime field \(\mathbb{F}_p\), a short Weierstrass curve is defined by the equation:

\[y^2 \equiv x^3 + ax + b \pmod p\]

To perform point addition and point doubling, standard cryptographic formulas rely primarily on the coordinates of the points and the curve parameter \(a\). Strikingly, the parameter \(b\) does not appear in the standard addition formulas.

When a protocol receives an untrusted point \(P' = (x', y')\) and does not explicitly check that \((y')^2 \equiv (x')^3 + ax' + b \pmod p\), the scalar multiplication algorithm still runs. However, mathematically, it is not operating on the intended curve \(E\). Instead, it computes on an alternate curve \(E'\) defined by:

\[y^2 \equiv x^3 + ax + b' \pmod p \quad \text{where} \quad b' = (y')^2 - (x')^3 - ax' \pmod p\]

The operation successfully computes \(Q' = [d]P'\), where \(d\) is the victim's secret key, but the calculation occurs entirely within the group of points on \(E'(\mathbb{F}_p)\).

Group Order Smoothness and Small Subgroups

A secure elliptic curve is deliberately chosen such that its group order \(N = \#E(\mathbb{F}_p)\) is either prime or contains a very large prime factor, making the Elliptic Curve Discrete Logarithm Problem (ECDLP) intractable.

However, the invalid curve \(E'\) chosen by the attacker does not share this protection. By varying the chosen point \((x', y')\), the attacker selects an arbitrary \(b'\), which alters the group order \(\#E'(\mathbb{F}_p)\). Attackers systematically search for parameters that yield a "smooth" group order—one that factors into many small primes:

\[\#E'(\mathbb{F}_p) = r_1^{e_1} \cdot r_2^{e_2} \cdots r_k^{e_k}\]

The attacker then chooses an invalid point \(P'\) that generates a subgroup of a very small prime order \(r\).

Solving the Discrete Logarithm Modulo Small Primes

When the victim computes the shared secret \(Q' = [d]P'\) using their secret scalar \(d\), they inadvertently project the secret key into the small subgroup generated by \(P'\).

Because the order \(r\) of \(P'\) is small (often under \(2^{32}\)), the attacker does not need to solve the ECDLP across the full cryptographic field. Instead, they only need to solve it within the small subgroup:

\[Q' = [d \pmod r]P'\]

An attacker can determine the value \(k_i \equiv d \pmod r\) almost instantaneously using standard algorithms such as Baby-step Giant-step or Pollard's rho algorithm, or even via brute force if \(r\) is sufficiently small.

Private Key Reconstruction via the Chinese Remainder Theorem

A single query reveals the private key modulo \(r\). To recover the full private key, the attacker repeats the process:

  1. Select a new invalid point \(P_i\) on a curve with a different small prime order \(r_i\), where all \(r_i\) are coprime.
  2. Send \(P_i\) to the victim and receive the resulting point or derive it from subsequent protocol behavior (such as error messages, authentication tags, or shared keys).
  3. Compute the residue \(k_i \equiv d \pmod{r_i}\).

Once the product of these small prime factors exceeds the total magnitude of the private key:

\[\prod_{i=1}^{m} r_i > d\]

The attacker applies the Chinese Remainder Theorem (CRT) to combine the system of congruences:

\[\begin{cases} d \equiv k_1 \pmod{r_1} \\ d \equiv k_2 \pmod{r_2} \\ \vdots \\ d \equiv k_m \pmod{r_m} \end{cases}\]

This reconstructs the exact integer value of the private key \(d\) in polynomial time, completely compromising the system's security without ever breaking the underlying cryptography of the intended curve.
