Evil Twin Captive Portal Attacks on Wi-Fi

This article examines how threat actors deploy rogue "Evil Twin" access points coupled with fraudulent captive portals to intercept and harvest enterprise Wi-Fi credentials. It outlines the technical mechanics behind the attack—from radio frequency spoofing to DNS redirection—explores how social engineering principles are applied within the portal interface, and highlights essential defensive countermeasures organizations must implement to safeguard their networks.

Understanding the Evil Twin Architecture

An Evil Twin attack relies on deploying a rogue wireless access point (AP) configured to mimic a legitimate network. Attackers configure the rogue device with the identical Service Set Identifier (SSID) and, in many cases, clone the Media Access Control (MAC) address (BSSID) of the authorized corporate network.

Because client devices running standard 802.11 protocols typically prioritize access points based on signal strength and known network profiles, the attacker often transmits at higher power or forces legitimate users to disconnect. Disconnection is frequently achieved through 802.11 deauthentication frames—unencrypted management frames sent to the client or broadcast to the entire network—compelling targeted devices to drop their current connection and seek the strongest available signal matching their saved profile, which is now the attacker's rogue AP.

Manipulation of Captive Portals

While enterprise-grade Wi-Fi commonly relies on WPA2/WPA3-Enterprise (802.1X) authentication, attackers frequently set up the Evil Twin as an open network or a misconfigured secondary network, presenting a captive portal to circumvent complex cryptographic handshakes.

A captive portal forces a connecting client to interact with a web page before being granted network access. In a rogue configuration, the manipulation proceeds through several key steps:

  1. Network Association: The victim device associates with the rogue AP. The rogue AP's DHCP server assigns the client an IP address, a default gateway pointing to the attacker's machine, and a rogue DNS server address.
  2. DNS Hijacking: When the victim attempts to navigate to any website, or when the operating system's automatic Network Connectivity Status Indicator (NCSI) triggers an HTTP request, the rogue DNS server resolves all queries to the attacker’s local web server IP address rather than the legitimate destination.
  3. HTTP Redirection: The web server running on the rogue AP intercepts incoming traffic and returns an HTTP 302 redirect, forcing the victim’s browser or built-in captive portal assistant to display the attacker's credential harvesting interface.

The Credential Harvesting Mechanism

The hosted captive portal is designed to mirror legitimate enterprise branding, IT support portals, or network login prompts. The harvesting process relies on deceptive user workflows:

  • Simulated Network Upgrades: The portal may claim that a firmware update, security certificate renewal, or authentication failure requires the user to re-enter corporate network credentials, such as their username and domain password.
  • WPA-Enterprise Credential Prompts: Attackers often present forms specifically requesting Active Directory or RADIUS credentials, exploiting users' familiarity with enterprise single sign-on (SSO) workflows.
  • Credential Logging: Upon submission, the web server stores the cleartext credentials or logs them for immediate operational use, after which the victim is either redirected to the legitimate internet (if the attacker is bridging connections) or shown a generic error message instructing them to wait.

Defensive Countermeasures

Protecting against rogue access points and credential harvesting requires a combination of technical controls, endpoint hardening, and user awareness:

  • Protected Management Frames (802.11w): Enforcing 802.11w prevents unauthorized deauthentication and disassociation frames, neutralizing the primary method attackers use to forcibly kick devices onto a rogue AP.
  • Wireless Intrusion Prevention Systems (WIPS): Modern enterprise network controllers utilize continuous radio frequency scanning to detect rogue access points broadcasting corporate SSIDs or unauthorized MAC addresses, allowing administrators to locate and suppress rogue broadcasts automatically.
  • Strict 802.1X Machine and Certificate Authentication: Deploying certificate-based Extensible Authentication Protocol (such as EAP-TLS) ensures that devices authenticate using cryptographically signed certificates installed on the hardware, eliminating the reliance on user passwords for Wi-Fi access entirely.
  • Mobile Device Management (MDM) Policies: Managing corporate devices via MDM allows security teams to disable auto-join features for open networks and prohibit manual captive portal interaction on unknown networks.
  • Security Awareness Training: Educating personnel to recognize that legitimate corporate networks rarely prompt for Active Directory credentials via an open browser window significantly reduces the likelihood of manual credential submission.
