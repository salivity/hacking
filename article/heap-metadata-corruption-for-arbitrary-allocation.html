Heap Metadata Corruption for Arbitrary Allocation

Heap metadata corruption enables attackers to manipulate an allocator's internal tracking structures, tricking it into returning user-controlled memory locations instead of legitimate heap buffers. In binary exploitation, gaining arbitrary allocation is a critical milestone that allows attackers to write to arbitrary memory addresses, overwrite function pointers, hijack execution flow, and achieve arbitrary code execution. This article examines the primary techniques used against heap implementations like glibc’s ptmalloc—including Tcache Poisoning, Fastbin Corruption, the House of Force, and the House of Spirit—to manipulate chunk metadata and force allocators to return chosen targets.

Tcache Poisoning

Modern implementations of glibc (starting from version 2.26) utilize a per-thread caching mechanism called the tcache. The tcache speeds up allocation by storing recently freed small chunks in singly linked lists organized by size. In its basic implementation, the tcache lacks extensive integrity checks.

In a tcache poisoning attack, an attacker exploits a heap vulnerability—such as a heap-based buffer overflow or a Use-After-Free (UAF)—to overwrite the next pointer of a freed chunk currently residing in a tcache bin. Because the allocator trusts this pointer, the poisoned address is treated as the next available free chunk. After a legitimate allocation consumes the initial chunk, the subsequent malloc call for that size class returns the forged pointer, providing the attacker with an arbitrary chunk anywhere in memory (e.g., targeting __free_hook, global offset tables, or stack frames).

Fastbin Duplication and Poisoning

Similar to the tcache, the fastbin mechanism handles smaller allocations using singly linked, Last-In-First-Out (LIFO) lists. Fastbin corruption occurs when an attacker modifies the forward (fd) pointer of a freed chunk in the fastbin.

Unlike the default tcache, the allocator verifies that the size field of the chunk pointed to by the fd pointer matches the size index of the fastbin being requested. To bypass this constraint, an attacker must identify or craft a valid fake size header at the target location before poisoning the fd pointer. Once the allocator links the fake chunk into the fastbin, subsequent allocations exhaust the preceding chunks and ultimately return the target address.

The House of Spirit

Rather than overwriting an existing free chunk's pointers, the House of Spirit technique involves manufacturing an entire fake chunk inside memory the attacker controls, such as the stack or the .bss segment.

The attacker sets up valid chunk metadata—specifically the size field and the subsequent chunk's size field to pass boundary checks—and then passes the address of the forged user data to free(). The allocator validates the metadata, assumes the chunk is legitimate, and inserts it into a bin (typically the tcache or fastbins). When an allocation of that size is subsequently requested, the allocator serves the crafted chunk, effectively granting read and write capabilities over the target memory region.

The House of Force

The House of Force targets the top chunk (also known as the wilderness chunk), which represents the remaining contiguous free space at the border of the heap used to service allocations when bins cannot satisfy a request.

This technique operates through the following sequence:

  1. Top Chunk Corruption: A buffer overflow overwrites the size field of the top chunk with an extremely large unsigned value (such as -1 or SIZE_MAX).
  2. Bypassing Expansion: With an inflated size, the allocator assumes it has enough space to service virtually any allocation request without needing to expand the heap via brk or mmap.
  3. Calculated Offset Allocation: The attacker requests an allocation of a specifically calculated size. This size is calculated as the distance between the top chunk's current address and the target destination minus chunk overhead. This request forces the top chunk pointer to shift directly to the attacker's designated address.
  4. Target Allocation: A subsequent malloc call returns the target address, granting the attacker arbitrary allocation capabilities.

Mitigations and Evolution

Modern allocators have implemented defensive checks to detect and prevent metadata corruption. Protections include safe-linking (pointer mangling via XOR and bit-shifting applied to next and fd pointers), double-free checks on tcache bins, alignment verification, and top chunk size sanity checks. While these defenses increase exploitation complexity, the fundamental principle remains: manipulating internal allocator metadata transforms localized memory corruption into arbitrary allocation control.
