Merkle-Damgård Length Extension Attacks Explained

This article explores how the underlying mathematical structure of Merkle-Damgård hash functions enables hash length extension attacks. Merkle-Damgård designs process data sequentially through an iterative compression function where the final hash output directly reflects the internal state of the algorithm. By examining the absence of a distinct finalization transform, the deterministic nature of length padding, and the state-continuation properties of the compression function, this guide breaks down why naive message authentication constructions fail against this specific cryptographic exploit.

The Merkle-Damgård Construction

The Merkle-Damgård construction transforms a fixed-length compression function into an arbitrary-length cryptographic hash function. Given an input message \(M\), the algorithm operates as follows:

  1. Padding: The message \(M\) is appended with padding bits so that its total bit length becomes a multiple of a fixed block size \(b\) (typically 512 or 1024 bits). Merkle-Damgård strengthening requires the padding to include a '1' bit, a sequence of '0' bits, and the binary representation of the original message length \(|M|\).
  2. Block Splitting: The padded message is divided into \(k\) uniform blocks: \(M_1, M_2, \dots, M_k\).
  3. Iterative Processing: The algorithm initializes an internal state with a public initialization vector (\(IV\)). It then iteratively applies a compression function \(f\): \[H_0 = IV\] \[H_i = f(H_{i-1}, M_i) \quad \text{for } 1 \le i \le k\]
  4. Output: The output hash is the final state: \(\text{Hash}(M) = H_k\).

Standard algorithms utilizing this construction include MD5, SHA-1, SHA-256, and SHA-512.

Mathematical Properties Enabling the Attack

A length extension attack occurs when an attacker knowing only \(\text{Hash}(Secret \parallel Message)\) and the length of \(Secret \parallel Message\) can compute \(\text{Hash}(Secret \parallel Message \parallel Padding \parallel Extension)\) without knowing the contents of \(Secret\). Three core mathematical properties enable this exploit.

1. Equivalence of Internal State and Output

In standard Merkle-Damgård hash functions, there is no irreversible finalization transformation applied to the last state variable. The final output is mathematically identical to the internal state:

\[\text{Hash}(M) = H_k\]

Because the final hash is the internal state of the compression function after processing the final block \(M_k\), the hash output completely leaks the algorithm's state at that point in time. In cryptographic terms, the function is state-transparent at block boundaries.

2. Sequential State Continuability

The compression function \(f\) evaluates each block sequentially depending solely on two inputs: the current block \(M_i\) and the previous intermediate state \(H_{i-1}\).

\[H_i = f(H_{i-1}, M_i)\]

Because \(f\) does not depend on past blocks once their effect has been absorbed into \(H_{i-1}\), the calculation of future blocks requires only:

  • The state \(H_k\)
  • The new message block \(M_{k+1}\)

An attacker can set the initialization vector of the hash function to the known hash output (\(IV' = H_k\)) and compute:

\[H_{k+1} = f(H_k, M_{k+1})\]

This produces an output identical to a continuous execution of the hash function over all previous blocks followed by \(M_{k+1}\).

3. Deterministic and Reversible Padding

The padding rule (Merkle-Damgård strengthening) is deterministic and depends strictly on the total length of the preceding data. Let \(L\) denote the bit length of \(Secret \parallel Message\).

The exact sequence of padding bytes \(P\) can be calculated solely from \(L\):

\[P = \text{Pad}(L) = 100\dots0 \parallel \text{bin}_r(L)\]

Because an attacker can derive \(P\) simply by knowing or guessing \(L\), the original message boundaries are fully reconstructible. The attacker forms an extended message:

\[M_{\text{extended}} = Secret \parallel Message \parallel P \parallel Extension\]

From the perspective of the hash function, the sequence \((Secret \parallel Message \parallel P)\) forms an exact, valid sequence of complete blocks whose final processed state evaluates to \(\text{Hash}(Secret \parallel Message)\).

The Mechanics of the Attack

Assume an application generates a naive Message Authentication Code (MAC) via concatenation:

\[T = \text{Hash}(K \parallel M)\]

Where \(K\) is an unknown secret key, \(M\) is a known message, and \(T\) is the valid authentication tag.

  1. Length Determination: The attacker knows \(M\) and determines or guesses the length of \(K\). This gives the total length \(L = |K \parallel M|\).
  2. Padding Reconstruction: The attacker calculates \(P = \text{Pad}(L)\).
  3. State Extraction: The attacker extracts the internal state registers from \(T\). For algorithms like SHA-256, \(T\) consists of eight 32-bit words that directly correspond to the registers \(A, B, C, D, E, F, G, H\).
  4. State Extension: The attacker defines an arbitrary payload \(E\) (\(Extension\)). The attacker pads \(E\) based on the new total length, which is: \[L_{\text{new}} = L + |P| + |E|\] \[P_E = \text{Pad}(L_{\text{new}})\]
  5. Execution: The attacker initializes the hash algorithm's registers using the values extracted from \(T\), bypassing the standard \(IV\), and processes \(E \parallel P_E\): \[T' = \text{Compress}(T, E \parallel P_E)\]

The resulting tag \(T'\) is a mathematically valid signature:

\[T' = \text{Hash}(K \parallel M \parallel P \parallel E)\]

The attacker submits \(M \parallel P \parallel E\) alongside \(T'\), successfully forging a verified message without ever learning \(K\).

Prevention and Mitigations

The vulnerability stems from the naive prefix construction \(\text{Hash}(K \parallel M)\) combined with Merkle-Damgård's lack of finalization. Systems prevent this attack through alternative mathematical constructions:

  • HMAC (Hash-based Message Authentication Code): Uses a nested hashing structure \(\text{Hash}((K \oplus opad) \parallel \text{Hash}((K \oplus ipad) \parallel M))\). The outer hash absorbs the output of the inner hash, hiding the internal state of the message digest.
  • Truncated Outputs: Variants like SHA-384 and SHA-512/256 run on larger state sizes (512 bits) and discard part of the final state (outputting only 384 or 256 bits). Because the internal state cannot be fully reconstructed from the truncated output, extension attacks are computationally infeasible.
  • Sponge Constructions (SHA-3): Sponge functions (such as Keccak) separate internal capacity from the exposed rate. The internal capacity remains hidden from the output, inherently neutralizing length extension attacks.
