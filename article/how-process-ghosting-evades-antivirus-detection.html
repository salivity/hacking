How Process Ghosting Evades Antivirus Detection

Process ghosting is an advanced code injection technique that allows an attacker to execute malicious binaries by manipulating the Windows file-deletion lifecycle and memory-mapped sections. By marking a payload file for deletion before creating an executable image section and subsequently closing the file handle, the payload is removed from disk prior to actual process creation. This timing gap creates a blind spot for security software, preventing antivirus (AV) engines and Endpoint Detection and Response (EDR) agents from opening or scanning the underlying executable on disk while the process runs entirely from memory.

The Antivirus Detection Model

Traditional endpoint security solutions rely on filesystem minifilter drivers and kernel callbacks to detect threats:

  1. Minifilter Drivers: Security tools intercept I/O request packets (such as IRP_MJ_CREATE and IRP_MJ_CLEANUP) to scan files when they are written to disk or closed.
  2. Process Creation Callbacks: The Windows kernel provides the PsSetCreateProcessNotifyRoutineEx callback, notifying security solutions whenever a new process is instantiated. This callback delivers metadata, including the file path of the executable image, prompting security software to open and scan the file on disk before the process begins execution.

Process ghosting disrupts this model by ensuring that the on-disk file no longer exists by the time PsSetCreateProcessNotifyRoutineEx is triggered.

Mechanics of Process Ghosting

Process ghosting relies on the behavior of the Windows Object Manager, the Memory Manager, and the NTFS file system. The technique follows a specific execution flow:

1. Creating the File in a Delete-Pending State

The execution begins by creating a new file or opening an existing file with the DELETE access right. The handle is then modified using SetFileInformationByHandle with the FileDispositionInformation flag set to TRUE. This marks the file for deletion, meaning the operating system will remove the file from the filesystem as soon as all open handles to it are closed.

2. Writing the Malicious Payload

Despite being in a delete-pending state, the file can still be modified as long as the handle remains open. The binary content of the payload is written directly to the file using standard file-write APIs.

3. Creating an Executable Section

To execute code in Windows, the file must be mapped into memory as an executable image section. The system invokes NtCreateSection with the SEC_IMAGE flag, referencing the handle of the delete-pending file. The Windows Memory Manager allows section objects to be created from delete-pending files, mapping the PE (Portable Executable) headers and sections into kernel memory structures.

4. Deleting the File from Disk

Once the section handle is established, the original file handle is closed via NtClose. Because the file was marked for deletion upon closure and no further file handles remain, the filesystem deletes the file entry immediately. However, the section handle still persists in memory, retaining the mapped image.

5. Spawning the Process

With the file completely removed from the filesystem, the process is created using low-level native APIs:

  • NtCreateProcessEx creates the process object backed by the detached image section.
  • The Process Environment Block (PEB) and process parameters (such as command-line arguments and standard handles) are allocated and written to the target process memory.
  • An initial execution thread is created using NtCreateThreadEx.

Why Antivirus Filters Fail to Intercept It

Process ghosting specifically bypasses detection mechanisms through the following architectural flaws:

  • File Access Denial: When NtCreateProcessEx triggers the PsSetCreateProcessNotifyRoutineEx callback, the registered AV/EDR driver attempts to inspect the binary using the path provided in the callback. Because the file is already deleted, attempts to open the file handle fail with errors such as STATUS_FILE_DELETED, preventing signature matching or heuristic file scans.
  • Minifilter Evasion: Minifilter drivers typically defer intensive file scanning until IRP_MJ_CLEANUP occurs (when all user handles are closed). In process ghosting, closing the handle simultaneously removes the file, leaving nothing on disk for the minifilter to scan.
  • Absence of Typical Injection Artifacts: Unlike Process Hollowing, process ghosting does not require unmapping an existing legitimate section (NtUnmapViewOfSection) or writing across process boundaries (WriteProcessMemory) into an existing process, evading common behavioral telemetry rules.
  • Circumvention of Previous Mitigation: Previous techniques like Process Doppelgänging relied on NTFS Transactions (TxF), which Microsoft later heavily monitored and restricted. Process ghosting relies strictly on core filesystem disposition semantics and section mapping, functioning without the use of transactional APIs.
