Stealth Persistence: Shadow Administrators in Windows

Shadow administrator accounts represent a sophisticated persistence mechanism in Windows and Active Directory environments where accounts hold administrative-level control without belonging to well-known privileged groups like Domain Admins. Rather than relying on overt group memberships that trigger security alerts, adversaries exploit granular Access Control Entries (ACEs) and delegated permissions across the directory. Understanding how these hidden privileges are structured, how they grant effective domain compromise, and how to detect them is critical for securing enterprise identity infrastructure.

The Concept of a Shadow Administrator

Traditional access management relies on role-based access control and security groups (such as Enterprise Admins, Domain Admins, or Account Operators). Because security monitoring tools and Security Information and Event Management (SIEM) solutions closely track changes to these sensitive groups, direct additions are easily detected.

To bypass this visibility, an adversary seeks "stealth privilege escalation" or persistence by granting specific, subtle Active Directory permissions to a seemingly standard user account. These accounts do not show up in privileged group enumerations, but the Discretionary Access Control Lists (DACLs) associated with directory objects grant them the ability to seize control of the domain whenever required.

Key Permissions Leveraged for Stealth Administration

Shadow administrative capability typically stems from specific Active Directory rights delegated directly on organizational units (OUs), sensitive groups, or high-privilege user accounts:

  • GenericAll / Full Control: Grants complete control over the target object. When placed on a user object, the holder can reset the password, disable security restrictions, or modify user attributes without belonging to an administrative group.
  • WriteDacl: Allows the holder to modify the security permissions of the target object. An attacker with this right can grant themselves GenericAll or add themselves to the object's access list dynamically when needed.
  • WriteOwner: Enables changing the owner of an object. Once ownership is assumed, the new owner inherently possesses the ability to rewrite the object's DACL.
  • ResetPassword (User-Force-Change-Password): Permits resetting passwords on target accounts. If delegated over privileged user objects or service accounts, it allows lateral movement or privilege escalation directly.
  • Directory Synchronization Rights (DS-Replication-Get-Changes-All): Often associated with domain replication services, these extended rights enable the replication of password hashes directly from the domain controller (a technique commonly known as DCSync).

Mechanics of Establishing Hidden Administrative Paths

Attackers establish or identify shadow admin paths through several vectors:

  1. Over-Delegation: Administrative tasks are frequently delegated at the OU level to allow help desk staff to reset passwords or manage group memberships. If privileged accounts reside within these managed OUs, the delegated accounts unintentionally inherit control over those privileged identities.
  2. Transitive Access and Chained Relationships: Control can be distributed across multiple steps. For instance, Account A might have permission to modify Group B; Group B may have write permissions to a script; that script might be executed by a Domain Admin. This creates an indirect path to complete control that rarely surfaces in traditional audits.
  3. Abuse of the AdminSDHolder Object: The AdminSDHolder object in Active Directory serves as a security template for protected accounts and groups. If an attacker modifies the DACL of the AdminSDHolder object itself, the changes are automatically propagated to all protected groups (like Domain Admins) by the background SDProp process, granting persistent access under the radar.

Detection and Defensive Strategies

Mitigating the risk of shadow administrators requires shifting security audits from simple group membership reviews to graph-based and ACL-centric security analysis.

  • Graph-Based Identity Auditing: Use tools that analyze relationships and effective permissions within Active Directory to map all paths leading to domain dominance. Auditing must evaluate transitive rights rather than static lists.
  • Monitoring Sensitive ACL Modifications: Ingest and monitor Windows Event ID 4662 (An operation was performed on an object) and Event ID 5136 (A directory service object was modified), particularly targeting changes to high-value OUs, the AdminSDHolder container, and directory-level extended rights.
  • Separation of Privileged Assets: Ensure domain administrative accounts, tier-zero assets, and domain controllers are segregated in secure Organizational Units that have inheritance blocked and no delegated rights assigned to general user populations.
  • Regular Review of Replicating Directory Changes: Audit accounts holding directory replication rights to ensure only legitimate domain controllers and authorized synchronization accounts (such as Azure AD Connect) hold replication privileges.
