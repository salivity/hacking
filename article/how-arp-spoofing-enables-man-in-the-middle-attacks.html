How ARP Spoofing Enables Man-in-the-Middle Attacks

Address Resolution Protocol (ARP) spoofing is a technique used by malicious actors to position themselves between two communicating devices on a local area network, establishing a man-in-the-middle (MitM) position. Because the ARP protocol inherently lacks authentication, an attacker can transmit forged ARP replies across the local subnet, poisoning the ARP caches of target devices. By linking their own Media Access Control (MAC) address to legitimate IP addresses—such as the default gateway—the attacker forces network traffic intended for other systems to route directly through their machine, permitting stealthy interception, inspection, modification, or termination of communications.

The Role and Vulnerability of ARP

In an IPv4 Ethernet network, devices use the Address Resolution Protocol to map dynamic Layer 3 IP addresses to physical Layer 2 MAC addresses. When Host A wants to communicate with Host B or the default gateway, it checks its local ARP cache. If no mapping exists, Host A broadcasts an ARP request asking which device owns the target IP. The device possessing that IP normally responds with an ARP reply containing its MAC address.

The fundamental weakness of ARP is that it is stateless and trust-based. Devices accept ARP replies even if they never sent a corresponding request, and they do not verify the sender's identity.

How the Attacker Intercepts Communications

To execute an ARP spoofing attack and initiate a man-in-the-middle exploit, an attacker connected to the same local broadcast domain follows these operational steps:

  1. Crafting Forged ARP Responses: The attacker generates gratuitous or unsolicited ARP reply packets. One packet is sent to the target victim stating that the router's IP address maps to the attacker’s MAC address. A second packet is sent to the local router/gateway stating that the victim's IP address maps to the attacker’s MAC address.
  2. Poisoning the ARP Cache: Both the victim machine and the gateway receive these illegitimate replies and automatically update their internal ARP tables to reflect the attacker's MAC address for the respective IP addresses.
  3. Diverting the Traffic Flow: When the victim attempts to send network traffic to the internet or other subnets, the system looks up the gateway's IP in its poisoned cache and constructs an Ethernet frame addressed to the attacker's MAC address. Conversely, any traffic returning from the external network through the gateway destined for the victim is also framed with the attacker's MAC address.
  4. Enabling Packet Forwarding: To prevent the connection from dropping—which would alert the victim to a network malfunction—the attacker enables packet forwarding on their network interface. The attacker's operating system receives the frames, inspects or modifies the payload, and re-transmits the packets to the actual intended destination.

Impact of the Interception

Once traffic flows through the attacker's host, the man-in-the-middle condition is complete. The attacker gains the capability to:

  • Eavesdrop on Data: Inspect unencrypted protocols (such as HTTP, FTP, Telnet, or DNS) to harvest sensitive credentials, session tokens, and personal data.
  • Downgrade Security: Execute SSL/TLS stripping attacks to force connections over plain HTTP.
  • Alter Traffic: Inject malicious payloads, rewrite DNS queries to divert the user to phishing sites, or alter data mid-transit.
  • Denial of Service (DoS): Silently drop packets instead of forwarding them, severing the victim's connection to the local network or internet.

Defenses against ARP spoofing generally require network-level controls, such as implementing Dynamic ARP Inspection (DAI) on managed network switches, configuring static ARP entries for critical systems, or employing encrypted network layers like IPsec and VPNs to secure payload data even if intercepted at the link layer.
