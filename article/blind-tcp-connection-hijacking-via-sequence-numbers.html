Blind TCP Connection Hijacking via Sequence Numbers

Historical TCP sequence number prediction was a critical vulnerability in early networking implementations that allowed remote attackers to execute blind connection hijacking across wide area networks without intercepting return traffic. By accurately calculating the Initial Sequence Numbers generated by predictable pseudo-random algorithms, an adversary could forge the identity of a trusted machine, complete a TCP three-way handshake blindly, and inject arbitrary commands into an active session. This article examines the mechanics of predictable TCP sequence numbers, the step-by-step process of wide area network blind spoofing, how attackers exploited IP-based trust relationships, and the architectural fixes that eventually mitigated the threat.

The Role of TCP Sequence Numbers

The Transmission Control Protocol ensures reliable, ordered data delivery over inherently unreliable IP networks. During the standard TCP three-way handshake:

  1. The client sends a SYN packet containing its Initial Sequence Number (\(\text{ISN}_C\)).
  2. The server acknowledges receipt with a SYN-ACK packet containing an acknowledgment number (\(\text{ISN}_C + 1\)) and its own Initial Sequence Number (\(\text{ISN}_S\)).
  3. The client completes the handshake with an ACK packet containing the acknowledgment number (\(\text{ISN}_S + 1\)).

Sequence numbers track data flow, verify packet reception, and reconstruct disordered packets. Crucially, a host will only accept incoming data if the sequence and acknowledgment numbers match the expected values within an active receive window.

The Predictability Flaw

Early implementations, derived from the original RFC 793 specification and 4.2/4.3BSD Unix codebases, generated sequence numbers predictably. Instead of using cryptographically secure random values, systems relied on simple formulas:

  • A global counter incremented by a fixed constant (for example, 128,000 or 250,000) every second.
  • An additional small, fixed increment added for every newly initiated connection.

Because clock drift across networks was relatively steady and the increments were linear, an attacker on a wide area network could probe a target server to deduce its internal sequence counter.

Mechanics of Wide Area Blind Connection Hijacking

Executing a blind TCP hijack across a WAN required overcoming a major barrier: because the attacker spoofed the source IP address of a trusted machine, the target's replies (including the critical SYN-ACK) were routed to the legitimate owner of that IP, not the attacker. The attack circumvented this through four coordinated phases.

1. Sampling and Latency Modeling

The attacker established several legitimate TCP connections to the target from their own real IP address. By recording the returned \(\text{ISN}_S\) values and measuring round-trip times, the attacker calculated:

  • The rate of the server’s internal sequence number counter.
  • The approximate transmission delay between the attacker and the target.
  • The expected \(\text{ISN}_S\) value at a precise future moment.

2. Silencing the Trusted Host

If the target sent a SYN-ACK to the spoofed host, that host would detect an unsolicited packet and immediately emit a RST (reset) packet, terminating the connection attempt. To prevent this, the attacker silenced the trusted host during the attack window. Across WANs, this was typically achieved via a Denial of Service attack, such as a TCP SYN flood directed at the trusted machine's listening ports. The flood exhausted the trusted host's connection backlog queue, rendering it incapable of processing or responding to incoming packets.

3. Initiating the Blind Handshake

With the trusted host incapacitated, the attacker sent a SYN packet to the target server containing:

  • Source IP: The IP address of the silenced, trusted host.
  • Destination IP: The target server's IP address.
  • Sequence Number: The attacker’s chosen \(\text{ISN}_C\).

The target processed the SYN and sent a SYN-ACK to the trusted host. The attacker never received this packet.

4. Blind ACK and Session Establishment

The attacker immediately sent a forged ACK packet to the target, again spoofing the trusted host's IP address. The packet contained:

  • Source IP: The trusted host.
  • Acknowledgment Number: The attacker’s calculated estimate of \(\text{ISN}_S + 1\).

If the attacker's prediction landed within the target's acceptable sequence window, the target considered the handshake complete and marked the TCP connection as established.

Payload Delivery and Trust Exploitation

Because the attacker operated blindly and could not read server responses, the attack targeted one-way execution vectors. In the late 1980s and 1990s, Unix environments frequently utilized Berkeley "r-commands" (rsh, rlogin, rcp). These services relied exclusively on IP address verification and local configuration files (/etc/hosts.equiv and ~/.rhosts) to grant administrative access without password challenges.

Once the connection was established, the attacker transmitted an application-layer payload inside a spoofed PSH-ACK packet containing the next predicted sequence numbers. Typical payloads appended permissive strings (such as + +) to the root user's ~/.rhosts file. This command instructed the operating system to trust any user connecting from any remote host, permanently opening interactive administrative access for the attacker without requiring further sequence prediction.

Resolution and Modern Defenses

The vulnerability was highlighted by Robert Morris in 1985 and demonstrated extensively in high-profile attacks, notably Kevin Mitnick's compromise of Tsutomu Shimomura's systems in 1994.

The security flaw was systematically eradicated through protocol and architectural updates:

  1. Cryptographically Secure ISN Generation: In 1996, RFC 1948 (formalized in RFC 6528) introduced an algorithm developed by Steven Bellovin. It generates ISNs using a cryptographic hash function combining the connection endpoints (local/remote IP and ports), a high-resolution timer, and a secret boot-time cryptographic key known only to the local kernel. This rendered ISNs unpredictable to external observers.
  2. Deprecation of IP-Based Trust: Services relying on source IP authentication were phased out in favor of cryptographic authentication protocols, primarily SSH (Secure Shell) and TLS, which enforce mutual authentication through public-key cryptography.
  3. Stateful Filtering: Modern firewalls and network devices track TCP state, drop packets that do not match active internal states, and often randomize sequence numbers in transit.
