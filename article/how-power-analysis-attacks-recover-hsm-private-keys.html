How Power Analysis Attacks Recover HSM Private Keys

Power analysis attacks recover private cryptographic keys from Hardware Security Modules (HSMs) by measuring and statistically analyzing the device's electrical power consumption during cryptographic operations. Even when an HSM's software interface is fully locked down and the cryptographic algorithms themselves are mathematically unbreakable, the underlying silicon must physically draw current to execute operations. By capturing these minute power fluctuations with an oscilloscope and correlating them with known cryptographic algorithms, an attacker can extract secret keys bit by bit.

The Physical Source of Information Leakage

HSMs rely on integrated circuits built using Complementary Metal-Oxide-Semiconductor (CMOS) technology. CMOS logic gates consume significantly more power when switching states (from 0 to 1 or from 1 to 0) than when remaining static, due to the charging and discharging of internal parasitic capacitances.

This behavior creates two primary data-dependent power models:

  • Hamming Weight: The instantaneous power consumption correlates directly with the number of 1 bits processed or held in a register at a given clock cycle.
  • Hamming Distance: The power consumption correlates with the number of bits transitioning from one state to another during a clock cycle.

Because internal electrical activity directly reflects the specific binary data moving across the data bus and through the arithmetic logic units, an HSM physically broadcasts its internal state through its power supply rail.

Gathering the Physical Measurements

To execute the attack, an adversary gains physical access to the target hardware. The attacker inserts a low-resistance shunt resistor in series with the HSM’s power supply or ground pin. By attaching a high-speed digital storage oscilloscope across this resistor, the attacker records the voltage drop over time, which directly corresponds to the current drawn by the cryptographic chip.

The attacker synchronizes the measurements using an external trigger—such as an I/O signal indicating the start of an encryption operation. The HSM is fed hundreds, thousands, or millions of known plaintexts or ciphertexts, and the oscilloscope captures the corresponding power trace for each distinct operation.

Attack Methodologies: SPA, DPA, and CPA

Attackers use three primary analytical methods to convert raw power traces into cryptographic keys:

1. Simple Power Analysis (SPA)

SPA relies on direct visual inspection of a single power trace or a small average of traces. It succeeds when the cryptographic algorithm’s execution path branches based on the value of a secret key bit.

  • In traditional RSA implementations using the "square-and-multiply" algorithm, a square operation occurs for every bit of the private exponent, but a multiply operation only occurs if the key bit is 1.
  • Because multiplication and squaring display distinct, visible power signatures, an attacker can read the private key directly from the oscilloscope display by identifying the sequence of operations.

2. Differential Power Analysis (DPA)

When algorithms are designed with constant-time execution to prevent SPA, attackers use DPA. DPA bypasses visual defenses by applying statistical analysis across thousands of power traces.

  • The attacker targets an intermediate value of the algorithm—typically the output of the first or last round of a block cipher like AES (such as the output of an S-box).
  • The attacker formulates a hypothesis for a small, manageable portion of the key (e.g., an 8-bit subkey, requiring only 256 guesses).
  • Based on the known plaintext and the subkey guess, the attacker calculates the expected intermediate value and divides the recorded power traces into two distinct sets based on a single target bit (e.g., set A where the bit is 0, and set B where the bit is 1).
  • The attacker calculates the mathematical difference between the averages of the two sets. If the key guess is incorrect, the difference approaches zero due to random noise. If the key guess is correct, a sharp statistical spike appears at the exact moment that intermediate state was computed in the hardware.

3. Correlation Power Analysis (CPA)

CPA is an advanced refinement of DPA that models the entire byte (using the Hamming Weight or Hamming Distance model) rather than just a single bit. The attacker calculates the Pearson correlation coefficient between the predicted power consumption of all subkey hypotheses and the actual measured power traces. The correct subkey yields the highest correlation value, requiring significantly fewer traces than standard DPA to successfully break the key.

Key Reconstruction

Because modern cryptographic algorithms process keys in discrete segments (such as 8-bit bytes in AES), an attacker does not need to guess a full 128-bit or 256-bit key simultaneously. Instead, the attacker applies DPA or CPA iteratively:

  1. Target the first byte of the key, testing only 256 possibilities to find the highest correlation peak.
  2. Fix the known first byte, then repeat the process for the second byte.
  3. Continue sequentially through each subkey until the entire key is recovered.

By reducing the complexity from an intractable brute-force search (\(2^{128}\)) to a trivial set of isolated subkey searches (\(16 \times 256\)), physical power analysis circumvents the mathematical security of the algorithm and completely extracts the private key from the HSM.
