CAN Bus Commands and Vehicle Hijacking Risks

Modern vehicles rely on the Controller Area Network (CAN) bus to enable communication between Electronic Control Units (ECUs) controlling vital functions such as steering, acceleration, and braking. Because the standard CAN protocol lacks built-in authentication and encryption, an attacker with access to the bus can inject fraudulent messages to manipulate physical systems. This article explains the types of commands used in automotive security research to influence steering and braking, the mechanisms behind these transmissions, and the industry defenses designed to mitigate these vulnerabilities.

The Mechanics of CAN Bus Communication

The CAN protocol operates on a broadcast architecture where every node receives every transmitted message. ECUs determine whether to process a frame based on its Arbitration ID (identifier) rather than a destination address. Standard CAN frames consist of:

  • Arbitration ID: Determines message priority and identity (e.g., 11-bit in standard CAN 2.0A, 29-bit in CAN 2.0B).
  • Control Field / Data Length Code (DLC): Specifies the number of data bytes (0 to 8 bytes in standard CAN).
  • Data Field: Contains the payload, often structured as bitfields or multi-byte values representing sensor readings, state flags, or actuator targets.
  • Cyclic Redundancy Check (CRC): Verifies data integrity across the physical wire, though it provides no cryptographic security.

Because CAN messages lack source authentication, an ECU cannot verify whether a frame originated from the legitimate sensor/controller or an unauthorized device attached to the bus.

Types of Commands Transmitted During Actuator Manipulation

Vehicle manufacturers utilize proprietary messaging structures for normal operation, alongside standardized diagnostic protocols for maintenance. Automotive researchers and threat actors target two primary categories of messages to influence safety-critical systems:

1. High-Frequency Normal Operational Frames (Spoofing and Flooding)

Under normal driving conditions, advanced driver-assistance systems (ADAS), such as lane-keep assist (LKAS) and adaptive cruise control (ACC), transmit continuous status and request frames to steering and braking actuators.

  • Steering Manipulation: An electric power steering (EPS) ECU typically listens for continuous angle, torque, or angular rate requests. In research demonstrations, manipulating steering requires transmitting spoofed steering angle or torque request packets at a higher frequency than the legitimate controller (e.g., if the camera module sends updates every 20ms, an injector might broadcast every 5ms to dominate the receiver buffer and arbitration).
  • Braking Manipulation: Autonomous emergency braking (AEB) or electronic stability control (ESC) systems receive deceleration or brake pressure demand messages. Injecting frames with maximum allowable deceleration values can trigger unintended braking events.

Most production ECUs incorporate counters (rolling counters) and proprietary checksums (such as CRC-8 or CRC-16 algorithms calculated over the payload and ID) to detect missing or corrupted frames. Successful injection of operational commands requires calculating valid counter increments and payload checksums in real time to prevent the receiving ECU from rejecting the packet or entering a fail-safe state.

2. Diagnostic and Routine Control Commands (UDS / ISO 14229)

Automotive diagnostics utilize the Unified Diagnostic Services (UDS) protocol over CAN (often mapped via ISO 15765-2 / ISO-TP). Diagnostic routines are designed to test hardware components during servicing and often have the authority to override operational software.

Key diagnostic mechanisms involved in system manipulation include:

  • Diagnostic Session Control (Service 0x10): Switches an ECU from the default session to an extended or manufacturing/development session (e.g., 0x10 0x03 for Extended Diagnostic Session). Certain actuations are strictly prohibited in the default session.
  • Security Access (Service 0x27): High-privilege actions frequently require seed-key authentication. If an attacker bypasses or authenticates via Service 0x27, they gain elevated rights on the target ECU.
  • InputOutputControlByIdentifier (Service 0x2F): This service allows diagnostic tools to directly command an ECU's input and output lines. For example, a command can instruct an ABS/ESC unit to actuate brake valves or command a steering motor to step through angle calibrations, bypassing high-level driver inputs entirely.
  • RoutineControl (Service 0x31): Used to start, stop, or query specific internal testing routines pre-programmed into the ECU firmware, such as initiating an automated bleed procedure for hydraulic brakes or calibrating steering center.

Unlike operational spoofing, using diagnostic overrides while a vehicle is in motion typically requires circumventing speed-threshold checks implemented in ECU firmware, as standard safety logic rejects diagnostic actuation when wheel speeds exceed zero.

Bus Flooding and Denial of Service (DoS)

Before an injected command can successfully steer or stop a vehicle, the legitimate ECU transmitting valid control data must often be silenced. Attackers achieve this through:

  • Priority Dominance: Continuously transmitting frames with an Arbitration ID of 0x000 (the highest priority on a CAN network), which causes other nodes to back off during arbitration and starves the bus of legitimate traffic.
  • Targeted Bus-Off Attacks: Exploiting the CAN error-handling state machine by deliberately corrupting messages from a specific ECU (e.g., using precise voltage injection on recessive bits) until that ECU reaches the "Bus Off" threshold and disconnects from the network, allowing injected control frames to operate without competition.

Defensive Mitigations

Automotive manufacturers and standards organizations have implemented several architectural defenses to prevent unauthorized frame injection:

  • Secure On-Board Communication (SecOC): Defined within the AUTOSAR standard, SecOC introduces Message Authentication Codes (MACs) and freshness values (counters or timestamps) into CAN payloads, ensuring that only authenticated nodes can issue control requests.
  • Central Gateway Segmentation: Modern architectures isolate safety-critical powertrain and chassis networks from infotainment, telematics, and OBD-II ports using secure hardware gateways that filter unauthorized message routing.
  • CAN FD and Cryptographic Hardware: Newer platforms adopting CAN with Flexible Data-Rate (CAN FD) utilize increased payload sizes (up to 64 bytes) to accommodate robust cryptographic signatures and integrate Hardware Security Modules (HSMs) directly inside ECUs.
