Sudoers Configuration Mistakes and System Takeover

The /etc/sudoers file governs administrative rights on Unix and Linux systems, dictating precisely which users can execute commands with elevated root privileges. When administrators introduce configuration errors—such as granting permissions to binaries with shell-escape capabilities, using unsafe wildcards, or misconfiguring environment handling—attackers can exploit these rules to bypass security boundaries. By escalating from an unprivileged user to the root user, malicious actors gain unrestricted control over the operating system.

Exploitation of Living-off-the-Land Binaries

A frequent administrative mistake is granting a user sudo rights to seemingly harmless standard utilities without recognizing that these binaries support interactive shells or arbitrary file access. Security researchers categorize these as "GTFOBins."

For example, granting access to text editors, pagers, or compilers allows an attacker to break out into a root shell:

  • vim or vi: An attacker granted sudo vim can execute :!/bin/sh within the editor to spawn a root shell immediately.
  • less or more: Pagers allow command execution by typing !/bin/sh during file viewing.
  • find: Running sudo find . -exec /bin/sh \; -quit executes an interactive shell under root context.
  • awk: Running sudo awk 'BEGIN {system("/bin/sh")}' invokes an administrative shell directly.

When these binaries are granted ALL or even specific file-viewing permissions via sudo, the security boundary is effectively nullified.

Wildcard Misuse and Argument Injection

Using wildcards (*) in the sudoers specification often introduces command injection vulnerabilities. Administrators frequently attempt to restrict commands to specific subdirectories, such as:

user ALL=(ALL) /usr/bin/cat /var/log/*

Because the wildcard matches arbitrary characters, an attacker can exploit command-line flags or path traversal:

  1. Directory Traversal: Specifying /usr/bin/cat /var/log/../../etc/shadow allows an attacker to read the system password hashes.
  2. Argument Injection: If an allowed command interprets flags (such as --exec or -o), an attacker can supply those flags in place of the wildcard, turning a restricted command into an arbitrary code execution vector.

Dangerous Environment Variables: LD_PRELOAD and SETENV

The sudoers file controls which environment variables persist when switching contexts. If a configuration specifies the SETENV tag or includes dangerous variables in env_keep, privilege escalation becomes trivial.

The most critical variable is LD_PRELOAD, which instructs dynamic linkers to load specified shared libraries before any others. If an attacker can execute a command with sudo while retaining control of LD_PRELOAD, they can compile a simple C library that spawns /bin/sh on initialization and load it during the execution of the permitted command:

sudo LD_PRELOAD=/tmp/exploit.so <allowed_command>

The preloaded library executes before the target application drops privileges or performs its intended task, instantly handing the attacker an interactive root shell.

Permissions on Sudoers and Included Files

The sudoers configuration is not limited to /etc/sudoers; it frequently parses /etc/sudoers.d/. If file permissions or directory permissions are set incorrectly (for example, allowing write access to non-root users or groups), an attacker does not need to exploit a binary. They can directly append an entry granting full root access:

attacker ALL=(ALL) NOPASSWD: ALL

Similarly, if an administrator grants sudo rights over file manipulation utilities (like cp, mv, tee, or sed), an attacker can overwrite /etc/sudoers or /etc/passwd to add a new administrative account.

Preventing Sudoers Takeover

Securing Unix systems against sudoers-based privilege escalation requires rigorous configuration practices:

  • Enforce Least Privilege: Never grant access to broad categories of commands or general-purpose utilities like editors, interpreters (Python, Perl, Bash), or pagers.
  • Avoid Wildcards: Explicitly define exact commands and scripts rather than relying on regex or shell wildcards.
  • Sanitize Environments: Ensure env_reset is active (the default in modern sudo installations) and never allow unvetted variables via env_keep.
  • Use visudo: Always edit configurations using visudo, which validates syntax and enforces strict file permissions before saving.
