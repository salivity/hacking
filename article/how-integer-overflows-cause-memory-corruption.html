How Integer Overflows Cause Memory Corruption

Integer overflows occur when an arithmetic operation attempts to create a numeric value that falls outside the range representable by a given number of bits. In low-level languages like C and C++, which lack automatic bounds checking, these arithmetic anomalies do not typically trigger exceptions or runtime errors; instead, values silently wrap around or truncate. When an application calculates memory allocation sizes, buffer bounds, or loop counters using tainted user input, an integer overflow can cause the program to allocate insufficient memory or bypass boundary validations. This flaw bridges the gap between simple arithmetic and critical memory corruption, enabling attackers to trigger heap or stack buffer overflows, overwrite critical memory structures, and hijack control flow.

The Mechanics of Integer Wrapping

Computers represent integers using fixed-width data types, such as 8-bit, 16-bit, 32-bit, or 64-bit registers. An unsigned 32-bit integer, for example, can hold values ranging from 0 to 4,294,967,295 (0x00000000 to 0xFFFFFFFF). When a program adds 1 to 0xFFFFFFFF, the register cannot accommodate the value 4,294,967,296. The hardware discards the carry bit, resetting the value to 0.

Similarly, signed integers use two's complement representation, where the most significant bit denotes the sign. In a 32-bit signed integer, adding 1 to the maximum positive value (2,147,483,647 or 0x7FFFFFFF) wraps the value to the minimum negative value (-2,147,483,648 or 0x80000000). While unsigned arithmetic wrapping is defined by language standards, signed integer overflow is undefined behavior in C/C++, often causing optimizing compilers to eliminate safety checks entirely.

Memory Allocation Size Mismatch

The most common path from an integer overflow to exploitable memory corruption involves dynamic memory allocation routines like malloc(), calloc(), or new[].

Programs frequently calculate buffer sizes dynamically based on user-supplied metrics, such as an array length:

void allocate_array(size_t count) {
    size_t buffer_size = count * sizeof(int); // Integer overflow risk
    int *array = (int *)malloc(buffer_size);

    for (size_t i = 0; i < count; i++) {
        array[i] = get_user_data(); // Heap out-of-bounds write
    }
}

If an attacker supplies a count value of 1,073,741,825 on a 32-bit system where sizeof(int) is 4:

  1. The multiplication 1,073,741,825 * 4 mathematically equals 4,294,967,300.
  2. As a 32-bit unsigned integer, this value wraps around to 4 (0x00000004).
  3. The program calls malloc(4), requesting a heap buffer large enough for only a single integer.
  4. The subsequent copy loop uses the original, un-overflowed count (1,073,741,825) as its termination condition.
  5. The loop writes data past the 4-byte allocation into adjacent heap memory, resulting in a heap-based buffer overflow.

Signed and Unsigned Comparison Flaws

Signedness bugs occur when signed values are implicitly converted to unsigned values, or vice versa, during conditional checks or memory operations.

Functions like memcpy(void *dest, const void *src, size_t n) expect the size parameter n to be of type size_t, which is unsigned. If an application validates a user-provided length using a signed integer, an attacker can bypass boundary defenses:

void process_packet(int user_len, char *user_data) {
    char local_buffer[256];

    // Signed comparison
    if (user_len > 256) {
        return; // Reject oversized input
    }

    // Implicit conversion to unsigned size_t
    memcpy(local_buffer, user_data, user_len);
}

If an attacker passes a negative value (such as -1) for user_len:

  1. The condition user_len > 256 evaluates to false because -1 is less than 256.
  2. When passed to memcpy, -1 is interpreted as an unsigned size_t, converting into 4,294,967,295 (on 32-bit systems) or 18,446,744,073,709,551,615 (on 64-bit systems).
  3. memcpy attempts to copy gigabytes of data into the 256-byte stack buffer, overflowing the stack frame immediately.

Converting Memory Corruption into Code Execution

Once an integer overflow creates an out-of-bounds memory write, an attacker leverages the corrupted memory space to gain control over program execution.

Heap Exploitation

On the heap, overflowing a dynamically allocated chunk allows an attacker to corrupt metadata used by the memory allocator, such as chunk size headers, forward pointers, and backward pointers in free-list implementations. Corrupting these structures during memory reallocation or deallocation (free()) can trigger primitive read/write operations anywhere in the process's address space (an arbitrary write primitive). Alternatively, attackers can overwrite adjacent heap-allocated objects containing C++ virtual method tables (vtable pointers) or function pointers, redirecting execution to shellcode or Return-Oriented Programming (ROP) chains when those functions are invoked.

Stack Exploitation

When signed conversion errors cause stack overflows, the out-of-bounds write overwrites local stack variables, saved frame pointers (RBP/EBP), and the function return address (RIP/EIP). By overwriting the return address, the attacker redirects execution flow to injected code or existing program routines when the vulnerable function returns.

Prevention and Safe Coding Practices

Preventing integer-induced memory corruption requires validating arithmetic before execution occurs:

  • Pre-Condition Checks: Ensure that operations do not exceed type limits prior to evaluation. For example, before computing count * sizeof(type), check that count <= SIZE_MAX / sizeof(type).
  • Compiler Built-ins: Modern compilers provide built-in arithmetic functions with overflow detection, such as GCC and Clang's __builtin_mul_overflow() and __builtin_add_overflow().
  • Safe Math Libraries: Utilize libraries designed to handle arithmetic operations with strict bounds checking and exception handling.
  • Strict Type Consistency: Match variable types with standard library signatures, strictly avoiding casting between signed and unsigned integers when manipulating sizes, lengths, or indices.
