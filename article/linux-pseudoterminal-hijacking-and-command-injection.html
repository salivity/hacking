Linux Pseudoterminal Hijacking and Command Injection

Pseudoterminal (PTY) hijacking is a post-exploitation technique in Linux environments where an attacker manipulates an active terminal session to execute unauthorized commands within the context of another logged-in user. By exploiting terminal subsystem interfaces, specifically terminal device files and control calls, an attacker can inject keystrokes directly into an active shell's input buffer. This article explains the underlying mechanics of pseudoterminals, how attackers leverage mechanisms like the TIOCSTI ioctl to inject commands, and how administrators can defend against this threat.

Understanding Linux Pseudoterminals

A pseudoterminal (PTY) provides a bidirectional communication channel that emulates a hardware terminal. In Linux, a PTY consists of two parts:

  1. PTY Master (ptmx): Handled by the terminal emulator (such as SSH daemon, GNOME Terminal, or tmux).
  2. PTY Slave (/dev/pts/X): The device file that the user's interactive shell (such as Bash or Zsh) connects to for standard input, standard output, and standard error.

When a user runs commands over an SSH session or inside a terminal emulator, the shell continuously reads user input from the slave device and writes command output back to it.

The Mechanism of Command Injection

Merely echoing data directly to a user's terminal slave device file (e.g., echo "command" > /dev/pts/1) only writes to the display buffer. This displays text on the target user's screen but does not execute it, because the input stream remains untouched.

To achieve command execution, an attacker must inject characters into the terminal's input queue as though they were physically typed by the targeted user. This is primarily accomplished through two methods:

1. The TIOCSTI ioctl System Call

The most common technique uses the TIOCSTI (Terminal I/O Control Simulate Terminal Input) request. When invoked via the ioctl system call, TIOCSTI pushes a single byte directly into the target terminal's input buffer.

An attacker who has compromised a user account or gained root access can execute a script that loops through an arbitrary command string, passing each character—followed by a newline character (\n)—to the target terminal descriptor using ioctl(fd, TIOCSTI, &byte). When the target user's shell reads from /dev/pts/X, it processes the injected characters as standard user input and immediately executes the payload.

2. Process Tracing and Shell Hijacking

If access to the terminal file or TIOCSTI is restricted, an attacker with appropriate privileges can use ptrace to attach to the target shell process running on the PTY. By intercepting system calls, modifying process memory, or redirecting file descriptors, the attacker can force the running shell to execute arbitrary commands without altering the visible state of the terminal.

Attack Scenarios and Implications

Attackers utilize PTY hijacking to achieve several tactical advantages:

  • Privilege Escalation via Sudo Hijacking: If a standard user has recently authenticated using sudo, an attacker running low-privilege background processes might attempt to hijack an elevated session before the credential cache timer expires.
  • Covert Lateral Movement: Root users can silently inject commands into specific user sessions to pivot into secure environments, cloud consoles, or internal networks where SSH keys are loaded into memory (ssh-agent).
  • Evasion of Shell History and Logging: Injected commands may bypass certain local logging frameworks or appear legitimately initiated by the victim, making forensic analysis and attribution difficult.

Mitigation and Hardening

Securing Linux environments against pseudoterminal injection involves disabling legacy terminal controls and restricting process introspection:

  • Disable TIOCSTI: Modern Linux kernels (version 6.2 and newer) allow disabling TIOCSTI globally using the sysctl parameter: 
    sysctl -w dev.tty.legacy_tiocsti=0
    Persist this by setting dev.tty.legacy_tiocsti = 0 in /etc/sysctl.d/99-disable-tiocsti.conf.
  • Restrict ptrace Scope: Prevent processes from attaching to other running processes by setting the Yama LSM ptrace scope: 
    sysctl -w kernel.yama.ptrace_scope=2
  • Enforce Strict File Permissions: Ensure the /dev/pts/ filesystem is mounted with secure options, ensuring users can only read and write to their own allocated terminal devices.
