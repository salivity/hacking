How Rolljam Devices Hack Rolling Code Systems

This article explains how Rolljam devices defeat modern vehicle security by intercepting and harvesting valid rolling codes from keyless entry fobs. While rolling code systems were designed to eliminate traditional replay attacks by rendering each transmitted code single-use, Rolljam bypasses this protection through a synchronized combination of radio frequency jamming and packet sniffing. By intentionally desynchronizing the key fob from the vehicle's receiver, the device steals an unused, authenticated code that allows an attacker to unlock the vehicle at will.

The Foundation: How Rolling Codes Work

Traditional remote keyless entry (RKE) systems were vulnerable to simple replay attacks, where a thief recorded an unlock signal and broadcasted it later to unlock the car. To prevent this, manufacturers introduced rolling code algorithms, typically based on proprietary encryption standards like KeeLoq.

Every time a user presses the key fob:

  1. The fob’s microcontroller uses an encryption key and a synchronized counter to generate a new, pseudo-random code.
  2. The vehicle receives the code, decrypts it using the shared secret key, and compares the counter value to its internal counter.
  3. If the received counter matches or falls within an accepted forward-looking window, the vehicle accepts the command and marks that specific code as expired, preventing it from ever being used again.

The Rolljam Attack Mechanism

Invented by security researcher Samy Kamkar, the Rolljam device exploits the physical layer of radio communication to defeat the mathematical security of the rolling code. It uses two radio transceivers: one to broadcast noise that jams the vehicle's receiver, and another, more sensitive transceiver to capture the signal from the key fob.

The attack operates in a multi-step sequence:

Step 1: The First Jam and Capture

When the vehicle owner approaches and presses the unlock button on their key fob, the fob broadcasts a valid code (Code A). The Rolljam device immediately transmits a targeted, narrow-band jamming signal on the car's operating frequency (typically 315 MHz or 433 MHz).

This interference drowns out the signal at the car’s receiver, preventing the vehicle from detecting the transmission. However, because the Rolljam device sits closer to the fob and uses a more sensitive receiver with tuned filtering, it cleanly intercepts and saves Code A without the vehicle ever receiving or invalidating it. To the user, the remote simply appeared to fail to register the press.

Step 2: The Second Jam and Replay

Naturally, the vehicle owner presses the unlock button a second time. The key fob advances its internal counter and transmits a new valid code (Code B).

The Rolljam device repeats its process: it continues jamming the vehicle's receiver and captures Code B. However, in the exact same millisecond, the Rolljam device transmits the previously stolen Code A.

Because the vehicle never heard Code A during the first attempt, Code A is entirely valid and authenticated. The vehicle accepts the transmission, unlocks the doors, and increments its internal counter. To the owner, the key fob simply required a second press to work normally.

The Exploit: Stolen Access

At the conclusion of the sequence, the vehicle's internal counter has consumed Code A and expects Code B (or a higher counter value) for the next operation. However, Code B was never received by the car—it is stored exclusively on the Rolljam device.

Because Code B has never been processed by the vehicle's onboard computer, it remains active, valid, and synchronized. The attacker can return to the vehicle at any point in the future and broadcast Code B to unlock the vehicle, open the trunk, or disarm the alarm system without triggering any alerts or showing signs of forced entry.

Mitigations and Modern Countermeasures

The Rolljam vulnerability exists because standard rolling code systems rely solely on sequence numbers without strict time constraints. Modern automotive security has evolved to counter signal-stealing techniques through several hardware and software upgrades:

  • Time-Based Rolling Codes: Similar to software two-factor authentication (TOTP), newer fobs integrate synchronized real-time clocks. Codes expire automatically after a few seconds, rendering a delayed replay attack useless.
  • Ultra-Wideband (UWB) and Time-of-Flight (ToF): Modern smart keys measure the exact time it takes for radio waves to bounce between the car and the fob. If a device attempts to intercept, manipulate, or relay the transmission, the added latency causes the vehicle to reject the signal.
  • Two-Way Cryptographic Handshakes: Instead of relying on a one-way broadcast from the remote, high-security systems require mutual authentication between the vehicle and fob before state-changing commands are accepted.
