Compromising Hybrid AD via Azure AD Connect

Azure AD Connect (now Microsoft Entra Connect) bridges on-premises Active Directory and cloud environments, synchronizing identities, credentials, and access policies. Because this server requires extensive privileges across both domains, it has become one of the most targeted components in hybrid enterprise networks. This article examines the primary methods attackers use to extract credentials from Azure AD Connect, escalate privileges, and pivot between on-premises and cloud infrastructures.

Extracting Stored Credentials via DPAPI

Azure AD Connect stores authentication credentials for both the on-premises Active Directory service account (commonly prefixed with MSOL_) and the cloud sync service account inside an internal SQL Server or LocalDB instance. These credentials are encrypted using the Windows Data Protection API (DPAPI).

An attacker who gains local administrator or NT AUTHORITY\SYSTEM access to the Azure AD Connect server can decrypt these databases. Using tools such as AADInternals or custom PowerShell scripts, the attacker can extract:

  • Cleartext credentials or NTLM hashes for the on-premises sync account.
  • OAuth tokens and credentials for the Azure AD/Entra ID directory synchronization service account.

DCSync Execution via the MSOL Account

By default, the on-premises MSOL_ service account generated during standard Azure AD Connect installations requires extended rights to synchronize directory changes. Specifically, it is routinely granted the Replicating Directory Changes and Replicating Directory Changes All permissions on the root domain object.

Once an attacker extracts the MSOL account credentials from the local database:

  1. The attacker can perform a DCSync attack against a domain controller without needing to compromise a Domain Controller directly.
  2. The attacker requests password hashes for any domain user, including the krbtgt account.
  3. With the krbtgt hash, the attacker can forge Kerberos Golden Tickets, resulting in full compromise of the on-premises Active Directory forest.

Cloud Privilege Escalation and Account Takeover

The cloud synchronization account possesses high-level access within the Microsoft Entra tenant to create, update, and delete synchronized objects. If an attacker recovers these cloud credentials, they can manipulate the tenant:

  • Soft Match and Hard Match Abuse: Attackers can manipulate synchronization attributes (such as userPrincipalName or immutableId) to bind an attacker-controlled on-premises identity to an existing un-synchronized cloud identity, effectively taking over privileged cloud accounts.
  • Password Overwrites: In configurations where Password Hash Sync (PHS) or password write-back is enabled, an attacker with sync privileges can overwrite or push arbitrary password hashes directly to cloud user accounts.

Custom Synchronization Rule Injection

Attackers with administrative control over the sync server can tamper with the Azure AD Connect Synchronization Service Manager. By configuring malicious transformation rules or modifying attribute mappings, an attacker can:

  • Force the synchronization of attributes that bypass established access controls.
  • Inject backdoor attributes into synchronized cloud objects.
  • Alter group memberships dynamically in the cloud without modifying the visible groups within on-premises management consoles.

Interception of Pass-through Authentication (PTA)

In environments utilizing Pass-through Authentication rather than Password Hash Sync, validation requests are sent from the cloud down to on-premises PTA agents. Attackers with administrative access to the server hosting the PTA agent can hook into the authentication pipeline. This enables the harvesting of cleartext credentials as users authenticate to Microsoft 365 and associated cloud services in real time.
