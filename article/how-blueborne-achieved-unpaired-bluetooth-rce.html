How BlueBorne Achieved Unpaired Bluetooth RCE

This article details how the BlueBorne vulnerability suite bypassed traditional security boundaries to achieve zero-click Remote Code Execution (RCE) over unpaired Bluetooth connections. Discovered in 2017, BlueBorne exposed fundamental architectural flaws in major Bluetooth implementations across Android, Linux, Windows, and iOS. By abusing pre-authentication protocols such as SDP, L2CAP, and BNEP, attackers could inject malicious payloads and gain control of targeted devices without requiring user interaction, prior pairing, or discoverable mode settings.

Bluetooth protocol stacks are divided into distinct layers, where fundamental connection negotiation must occur before any cryptographic pairing, authentication, or user authorization takes place. Operating systems listen for link-level requests to establish basic communication channels. BlueBorne exploited bugs residing within these early, unauthenticated layers, meaning that an attacker only needed the target device's Bluetooth to be active and within radio range (approximately 10 meters) to execute an attack.

The core mechanism for achieving RCE in Android centered on chaining an information leak with a memory corruption vulnerability. Attackers first exploited CVE-2017-0785, an information disclosure flaw in the Service Discovery Protocol (SDP). By sending crafted SDP requests containing malformed size attributes, the SDP server returned memory buffers beyond the intended data. This allowed the attacker to leak pointers, determine the layout of the device’s memory, and successfully defeat Address Space Layout Randomization (ASLR).

With ASLR bypassed, the attacker leveraged CVE-2017-0781 or CVE-2017-0782, vulnerabilities residing in the Bluetooth Network Encapsulation Protocol (BNEP). BNEP provides networking capabilities over Bluetooth, handling packet forwarding similarly to Ethernet. Due to improper input validation and missing bounds checks when parsing control messages, an attacker could trigger a heap-based buffer overflow. By sending oversized or maliciously structured BNEP packets, the attacker overwrote function pointers in the heap memory of the com.android.bluetooth process, steering the instruction pointer toward their injected shellcode.

On Linux systems, a similar vector targeted the Linux kernel's implementation of the Logical Link Control and Adaptation Protocol (L2CAP) via CVE-2017-1000251. The BlueZ stack failed to properly handle internal configuration buffers when processing L2CAP configuration responses. An attacker could transmit an unexpected, malformed configuration request that caused a stack-based buffer overflow directly within the kernel space, leading directly to arbitrary kernel-level code execution.

Because the vulnerable services executed within high-privilege system daemons or directly inside the OS kernel, successful exploitation granted full control over the device. Attackers gained access to system resources, filesystem data, network interfaces, and connected peripherals—all accomplished silently over the air without prompting a pairing request, alerting the user, or leaving traditional network log traces.
