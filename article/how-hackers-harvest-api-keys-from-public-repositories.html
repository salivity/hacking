How Hackers Harvest API Keys from Public Repositories

Automated scanning bots continuously monitor public code repositories to discover and exploit accidentally committed cloud API keys within seconds of publication. Threat actors leverage public event streams, regular expression matching, and entropy analysis to identify high-value credentials, followed by automated scripts that instantly test the validity of the harvested keys. Understanding this harvesting pipeline reveals why even a momentary leak can result in immediate infrastructure compromise.

Real-Time Event Stream Ingestion

Attackers do not rely on manual searches or periodic web scraping; instead, they tap into real-time public activity feeds provided by platforms like GitHub, GitLab, and Bitbucket. For example, GitHub provides a public Events API that broadcasts all platform actions, including push events, fork events, and public releases.

Scanning bots ingest this event stream at scale via continuous polling or webhooks. The moment a developer pushes a commit to a public repository, the bot receives an event payload containing the commit metadata and links to the modified code chunks (diffs). This allows attackers to evaluate code changes within milliseconds of their appearance online.

Pattern Matching via Regular Expressions

Once the raw code diffs are retrieved, bots run them through high-speed signature engines. Many cloud service providers use deterministic formats for their API keys, making them trivial to identify using regular expressions (regex).

Common targets include:

  • Amazon Web Services (AWS): Identifiers typically start with standard prefixes, such as AKIA for access key IDs, followed by 16 alphanumeric characters.
  • Google Cloud Platform (GCP): API keys frequently begin with the prefix AIza followed by 35 alphanumeric characters.
  • Third-Party Services: Services such as Slack, Stripe, Twilio, and GitHub themselves utilize structured prefixes (e.g., xoxb-, sk_live_, ghp_) to denote specific token scopes.

Regex scanning allows bots to discard irrelevant code instantly and isolate strings that strictly conform to known authentication token structures.

High-Entropy Analysis

Not all sensitive credentials conform to structured prefixes. Private SSH keys, database connection strings, and generic OAuth secrets often appear as arbitrary, pseudo-random character sequences.

To catch these unstructured secrets, bots use Shannon entropy algorithms. High entropy indicates a high degree of randomness, a characteristic typical of cryptographic keys and strong passwords compared to standard programming syntax or natural human language. By scanning variable assignments for high-entropy strings, bots uncover secrets that evade basic regex filters.

Deep Git History and Context Parsing

Amateur developers frequently attempt to fix a secret leak by making a subsequent commit that removes the key from the code. However, Git records the entire history of a project.

Harvesting bots are designed to parse the complete Git commit tree, including past revisions, detached heads, merged branches, and pull request comments. Even if a sensitive key is present in a repository for only a few seconds before being deleted, it remains permanently accessible in the commit history until the repository is forcefully purged and rewritten.

Automated Validation and Immediate Exploitation

Finding a matching string is only the first step; the final phase of the pipeline is validation. Attackers configure automated webhooks that pass extracted keys directly to specialized validation scripts.

  1. Fingerprinting and Privilege Checking: For an AWS key, the bot immediately calls non-destructive identity functions, such as sts:GetCallerIdentity, to verify if the key is active and determine the attached IAM policies.
  2. Automated Resource Hijacking: If the key possesses administrative or deployment privileges, secondary automated payloads execute within minutes. Attackers typically deploy unauthorized cloud compute instances for cryptocurrency mining, establish persistence by creating rogue administrative users, or harvest connected databases for sensitive corporate data.
