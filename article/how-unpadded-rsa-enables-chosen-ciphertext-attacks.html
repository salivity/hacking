How Unpadded RSA Enables Chosen-Ciphertext Attacks

Textbook RSA is inherently vulnerable to chosen-ciphertext attacks because it lacks cryptographic padding, which directly exposes its underlying multiplicative homomorphic property. Without padding, an attacker can mathematically manipulate an intercepted ciphertext such that a decryption oracle inadvertently decrypts the original message without ever processing the target ciphertext directly. This article explains the mathematical flaw in unpadded RSA, demonstrates how the chosen-ciphertext attack operates, and outlines how modern padding schemes neutralize the threat.

The Underlying Flaw: Multiplicative Homomorphism

Textbook RSA encrypts a plaintext message \(m\) using a public exponent \(e\) and modulus \(n\) through the formula:

\[c \equiv m^e \pmod n\]

Decryption reverses this using the private exponent \(d\):

\[m \equiv c^d \pmod n\]

Because textbook RSA relies on pure modular exponentiation, it possesses a multiplicative homomorphic property. If an attacker has two ciphertexts, \(c_1 \equiv m_1^e \pmod n\) and \(c_2 \equiv m_2^e \pmod n\), multiplying them yields:

\[c_1 \cdot c_2 \equiv (m_1 \cdot m_2)^e \pmod n\]

When decrypted, the product of the ciphertexts produces the product of the corresponding plaintexts. In a secure cryptosystem, altering the bits of a ciphertext should produce unpredictable noise upon decryption. In unpadded RSA, modifying the ciphertext produces mathematically predictable changes to the decrypted plaintext.

Executing the Chosen-Ciphertext Attack

In a standard chosen-ciphertext attack (CCA) scenario, an adversary intercepts a target ciphertext \(c\) that they wish to decrypt. While they do not have the private key \(d\), they have access to a decryption oracle—such as an automated server, a cryptographic token, or an API—that will decrypt arbitrary ciphertexts, with the exception of the intercepted ciphertext \(c\) itself.

Because the oracle rejects requests containing the exact value \(c\), the attacker uses the homomorphic property to disguise it:

  1. Blinding the Ciphertext: The attacker selects an arbitrary integer \(s\) such that \(\gcd(s, n) = 1\). They encrypt \(s\) using the target's public key, yielding \(s^e \pmod n\).
  2. Creating the Modified Ciphertext: The attacker computes a modified ciphertext \(c'\) by multiplying the intercepted ciphertext \(c\) by the encrypted factor: \[c' \equiv c \cdot s^e \pmod n\] Because \(c \equiv m^e \pmod n\), this is equivalent to: \[c' \equiv (m \cdot s)^e \pmod n\]
  3. Querying the Oracle: The attacker submits \(c'\) to the decryption oracle. Because \(c' \neq c\), the oracle accepts the input and performs the decryption: \[m' \equiv (c')^d \equiv ((m \cdot s)^e)^d \equiv m \cdot s \pmod n\]
  4. Extracting the Plaintext: The oracle returns the blinded result \(m'\) to the attacker. To recover the original secret message \(m\), the attacker calculates the modular multiplicative inverse of their chosen factor (\(s^{-1} \pmod n\)) and computes: \[m \equiv m' \cdot s^{-1} \pmod n\]

Through this process, the attacker completely bypasses access controls and decrypts the target message using a single query to the decryption oracle.

Why Padding Eliminates the Vulnerability

The attack succeeds entirely because textbook RSA treats any number between \(0\) and \(n-1\) as a valid, structured plaintext. To prevent this, real-world implementations require randomized padding schemes, most notably Optimal Asymmetric Encryption Padding (OAEP).

Padding schemes transform raw plaintext before modular exponentiation by:

  • Introducing High Entropy: Adding cryptographically secure pseudorandom bits ensures that encrypting the same message multiple times produces entirely different ciphertexts.
  • Enforcing Formatting Checks: OAEP uses hash functions and asymmetric feistel networks to structure the plaintext. If an attacker multiplies a valid ciphertext by \(s^e\), the decrypted value will not contain the mathematically strict formatting, fixed byte markers, or hash verification blocks required by the standard.

When an oracle decrypts a manipulated ciphertext protected by OAEP, the integrity verification fails immediately. The system rejects the payload and returns an error without revealing any numerical output, fully mitigating chosen-ciphertext attacks.
