AMD PSP Flaws Enabling Low-Level Firmware Hacks

The AMD Platform Security Processor (PSP), officially known as the AMD Secure Processor, is a dedicated ARM-based security co-processor embedded within modern AMD CPUs to serve as a hardware-level Root of Trust. Despite its isolated architecture, researchers have uncovered critical vulnerabilities ranging from buffer overflows to cryptographic validation weaknesses in its proprietary firmware. These flaws allow attackers with appropriate access to execute unauthorized code at the highest privilege level, effectively bypassing platform security mechanisms like Secure Boot, firmware Trusted Platform Module (fTPM) protections, and AMD Secure Encrypted Virtualization (SEV).

The Architecture and Privileges of the PSP

The PSP operates independently of the main x86 execution cores. Running its own operating system on an isolated ARM Cortex-A5 or similar core, the PSP controls cryptographic operations, platform initialization, key management, and the system boot sequence before the main CPU even initializes. Because it has unrestricted access to system memory, registers, and non-volatile storage, gaining execution control within the PSP grants an attacker deeper access than the OS kernel, hypervisor, or traditional System Management Mode (SMM).

Critical Vulnerabilities Enabling Low-Level Firmware Execution

Unauthorized firmware hacking and persistence within the PSP rely on several classes of vulnerabilities discovered over various CPU generations:

1. Stack-Based Buffer Overflows in Embedded Applications (Trustlets)

One of the most notable classes of vulnerabilities involves memory management errors within PSP "trustlets" (isolated applications running on the PSP's internal operating system).

  • Example (CVE-2018-8935): Discovered by researchers, this vulnerability stemmed from improper bounds checking in the PSP’s fTPM trustlet while parsing cryptographic certificates. An attacker with admin privileges on the host system could send a malformed certificate to the fTPM, causing a stack-based buffer overflow. This permitted arbitrary code execution inside the secure enclave, bypassing hardware-enforced boundaries.

2. Insufficient Firmware Verification and Cryptographic Bypass

The PSP is responsible for authenticating bootloader stages and system firmware (AGESA/BIOS) before passing control to the x86 cores. Several attack vectors target this verification process:

  • Signature Verification Flaws: Implementation bugs in cryptographic validation routines have historically allowed altered firmware modules to execute without triggering digital signature failures.
  • Rollback/Downgrade Vulnerabilities: Incomplete hardware anti-rollback enforcement allows attackers to flash older, officially signed firmware versions known to contain unpatched security bugs, which can then be exploited to escalate privileges.

3. Fault Injection and Hardware Glitching Attacks

Software-level validation within the PSP relies on the integrity of the underlying hardware signals. Physical attacks bypass software security by destabilizing the processor during critical verification routines:

  • FaulTPM Attack: Researchers demonstrated that voltage fault injection (voltage glitching) targeting the PSP during the secure boot phase could corrupt cryptographic instruction processing. This allows attackers to bypass code-signing verification, dump the volatile memory of the PSP, and extract sensitive data such as fTPM cryptographic keys, BitLocker encryption keys, and SEV secrets directly from the co-processor.

4. Shared Memory and DMA Attack Surfaces

The PSP communicates with the x86 host environment via shared system memory and Direct Memory Access (DMA) interfaces. Vulnerabilities arise when:

  • The PSP fails to enforce strict boundaries between host memory and internal secure registers.
  • Time-of-check to time-of-use (TOCTOU) race conditions occur when reading untrusted input from DRAM, allowing host-level code to swap malicious payloads into memory mid-verification.

Impact of Low-Level PSP Compromise

Successful exploitation of these vulnerabilities allows an attacker to execute arbitrary code within the PSP, leading to:

  • Permanent Platform Rootkits: Attackers can inject persistent code into non-volatile SPI flash memory that survives OS reinstallation, hypervisor resets, and BIOS reflashing.
  • Bypassing SEV Isolation: Compromising the PSP nullifies the security guarantees of AMD Secure Encrypted Virtualization (SEV), allowing host-level attackers to decrypt virtual machine memory in cloud environments.
  • Decryption of System Storage: Extracting sealed fTPM master keys allows unauthorized decryption of storage volumes protected by technologies like BitLocker or LUKS.

Mitigation and Defense

Remediating PSP-level vulnerabilities requires low-level firmware patches distributed through AMD Generic Encapsulated Software Architecture (AGESA) updates provided by motherboard manufacturers. Critical mitigations include:

  • Applying the latest motherboard BIOS updates to patch known memory management flaws in fTPM trustlets.
  • Enforcing physical protections, chassis intrusion detection, and hardware shielding to defend against localized voltage and clock glitching.
  • Implementing strict hardware-based anti-rollback fuses (eFuses) to prevent the deployment of legacy, vulnerable firmware revisions.
