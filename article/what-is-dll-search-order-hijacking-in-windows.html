What Is DLL Search Order Hijacking in Windows?

DLL search order hijacking is a technique where an attacker exploits the default mechanism Windows uses to locate and load Dynamic-Link Libraries (DLLs) into memory. By placing a malicious DLL with an identical name in a directory searched before the legitimate file, an attacker tricks a trusted application into executing arbitrary code. This article explains the underlying mechanics of the Windows search sequence, how adversaries leverage it for unauthorized execution and privilege escalation, and the standard practices used to prevent this vulnerability.

When a Windows application requires a DLL without specifying a fully qualified path, the operating system attempts to locate the file by scanning a predetermined series of directories. Under modern Windows systems with Safe DLL Search Mode enabled, the operating system checks directories in a specific sequence: the directory from which the application loaded, the system directory (such as C:\Windows\System32), the 16-bit system directory, the Windows directory, the current working directory, and finally, the directories listed in the system and user PATH environment variables.

The security risk arises when an application requests a DLL that is either missing from the system entirely (often referred to as a "phantom DLL") or located further down the search hierarchy. If an attacker possesses write permissions to any directory checked earlier in the search sequence—most commonly the application’s own directory or a folder included in the PATH—they can drop a malicious DLL bearing the target name into that location.

Once the application launches, the Windows loader parses the search order, encounters the attacker's DLL first, and loads it into the application’s process memory space. Upon loading, the DLL executes its initialization code, typically contained within the DllMain function. Because the operating system assumes the loaded module is legitimate, the attacker’s code runs automatically without raising native execution warnings.

This technique allows unauthorized code execution in several high-impact ways:

  • Privilege Escalation: If a vulnerable application runs as a high-privilege account, such as SYSTEM or an elevated administrator, the injected DLL executes within that elevated security context, granting the attacker full administrative control over the machine.
  • Defense Evasion: Because the payload runs inside a legitimate, often digitally signed process (such as a legitimate operating system utility or trusted third-party software), security monitoring tools and endpoint detection and response (EDR) solutions may fail to identify the malicious activity.
  • Persistence: Attackers frequently use DLL hijacking to maintain access to a compromised system. By placing a malicious DLL in the folder of an application configured to launch at system startup, the attacker ensures their code executes repeatedly with each reboot.

Preventing DLL search order hijacking requires software developers and system administrators to enforce strict controls. Developers can mitigate the issue by loading libraries using absolute paths via functions like LoadLibraryEx with flags such as LOAD_LIBRARY_SEARCH_SYSTEM32, or by using the SetDllDirectory API to remove the current working directory from the search order. Administrators can protect systems by ensuring strict access control lists (ACLs) on software installation directories, restricting standard user write access to directories in the system PATH, and auditing applications for insecure library-loading behavior.
