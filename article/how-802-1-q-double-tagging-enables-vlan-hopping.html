How 802.1Q Double Tagging Enables VLAN Hopping

VLAN hopping via 802.1Q double tagging is a Layer 2 network attack that enables an unauthorized device to bypass network segmentation and inject packets into an isolated Virtual Local Area Network (VLAN). By taking advantage of the way network switches process the native VLAN on trunk ports, an attacker can craft a maliciously structured frame that sheds its outer identification layer mid-transit, tricking downstream switches into delivering the payload to a restricted target network without routing authorization.

Prerequisites of the Attack

For a double-tagging attack to succeed, specific network conditions must be met:

  1. Native VLAN Alignment: The attacker must reside on an access port that belongs to the same VLAN assigned as the "native VLAN" on an adjacent 802.1Q trunk link (commonly the default VLAN 1).
  2. Trunk Port Architecture: The attack requires a switch-to-switch trunk link that processes frames using IEEE 802.1Q encapsulation.
  3. Untagged Native VLAN Configuration: The trunk link must be configured to transmit native VLAN traffic untagged, which is standard default behavior for many enterprise switches.

How Double Tagging Works

The exploitation process relies on encapsulating the payload with two distinct 802.1Q headers (tags) and depends on switches parsing headers sequentially:

  1. Frame Crafting: The attacker constructs an Ethernet frame containing two 802.1Q tags:

    • Outer Tag: Set to the native VLAN ID of the switch trunk (e.g., VLAN 1).
    • Inner Tag: Set to the unauthorized target VLAN ID that the attacker wants to compromise (e.g., VLAN 20).

  2. First Switch Processing: The frame enters the first switch through the attacker's port. Because the switch is configured to treat the native VLAN as untagged over the 802.1Q trunk, it assumes the outer tag is redundant before transmitting the frame across the trunk link. The switch strips away the outer VLAN tag and leaves the rest of the frame intact.

  3. Traversing the Trunk: The frame travels across the trunk to the second switch. Crucially, the inner VLAN tag (VLAN 20) is now exposed at the front of the frame as if it were the original tag.

  4. Second Switch Processing: The receiving switch inspects the incoming frame. Seeing the exposed inner tag (VLAN 20), it treats the frame as legitimate native traffic for VLAN 20. The switch strips the remaining tag and broadcasts or forwards the packet directly to the destination device's access port.

Limitations of the Attack

Double tagging is strictly unidirectional. Because the returning traffic from the victim device is generated inside the target VLAN, the network switches will route responses legitimately according to Layer 3 boundaries or drop them. The attacker cannot receive return packets over Layer 2. However, this one-way communication is sufficient to execute denial-of-service attacks, poison caches, exploit unauthenticated services, or trigger remote code execution payloads using connectionless protocols like UDP.

Prevention and Mitigation

Securing networks against double-tagging VLAN hopping requires removing the structural conditions the exploit relies on:

  • Tag the Native VLAN: Enable explicit native VLAN tagging globally on all switches (e.g., vlan dot1q tag native), forcing the switch to retain the outer tag rather than stripping it.
  • Assign an Unused Native VLAN: Change the native VLAN on all trunk ports to an isolated, dedicated VLAN ID that contains no access ports or user devices.
  • Disable Unused Ports and Auto-Trunking: Explicitly define access ports using non-trunking modes and disable Dynamic Trunking Protocol (DTP) to prevent rogue devices from negotiating trunk links.
