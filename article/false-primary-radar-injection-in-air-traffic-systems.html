False Primary Radar Injection in Air Traffic Systems

Injecting false primary radar returns into civilian air traffic management (ATM) systems involves manipulating the raw echo detection chain or tampering with downstream digital processing networks. Unlike Secondary Surveillance Radar (SSR) or Automatic Dependent Surveillance-Broadcast (ADS-B), which rely on transponder-based digital messages, Primary Surveillance Radar (PSR) measures passive radio frequency (RF) reflections bouncing off an aircraft's physical hull. To successfully insert phantom targets—often called "ghost aircraft"—adversaries exploit vulnerabilities across two distinct domains: the physical electromagnetic spectrum via specialized RF transmission, and the terrestrial digital networks that transport radar data to Air Traffic Control (ATC) displays.

Physical Layer: Radio Frequency Manipulation

To create synthetic primary returns directly at the radar receiver, an adversary must generate RF signals that convincingly mimic passive reflections of the radar's own transmitted pulses.

  • Digital Radio Frequency Memory (DRFM) Repeaters: DRFM devices intercept an incoming pulse from a civilian PSR, digitize it, modify its parameters (such as phase, frequency, and time delay), and re-transmit it back to the radar antenna. Because the re-transmitted signal matches the radar's original pulse shape and frequency modulation, the radar’s matched-filter receiver accepts it as a genuine echo. Modulating the return delay simulates range, while adjusting the Doppler frequency shift simulates velocity.
  • Synchronized Pulse Injection: If an attacker knows the pulse repetition frequency (PRF), scan rate, and operating band of a non-cooperative or simpler civilian radar, they can transmit synthetic pulses timed precisely to coincide with the radar antenna beam passing their location. This forces the receiver to register non-existent targets along that specific azimuth.
  • False Target Deception Jamming: By generating a cluster of delayed pulse replicas, an adversary can create multiple false tracks simultaneously. When designed correctly, these pulses overwhelm the radar’s Constant False Alarm Rate (CFAR) algorithms, forcing the processing pipeline to instantiate multiple valid "plots" where no physical object exists.

Processing Layer: Radar Plot Extractor Exploitation

At the physical radar installation, raw analog signals are converted into discrete target detections by a Radar Plot Extractor (RPE) or Radar Signal Processor (RSP).

  • Firmware and Calibration Tampering: If physical access or remote maintenance access to the radar head is compromised, an attacker can modify the calibration tables or digital signal processing (DSP) parameters. Modifying the CFAR threshold or injecting pre-programmed synthetic target vectors directly into the DSP firmware generates false target coordinates before any external verification occurs.
  • Sensor Interface Poisoning: Intercepting the analog or digitizer buses (such as intermediate frequency inputs to analog-to-digital converters) via rogue hardware implants allows attackers to inject false voltage spikes corresponding to target reflections, bypassing all RF transmission hurdles entirely.

Network Layer: Surveillance Data Link Interception

Modern civilian air traffic management architectures rarely transmit raw analog radar signals over long distances. Instead, the radar digitizer translates detected returns into standardized digital data packets—most commonly the Eurocontrol Standard Format for Radar Data Exchange (ASTERIX), specifically categories such as CAT 001 or CAT 048 for monoradar target reports.

  • Man-in-the-Middle (MitM) Attacks on Telemetry Backhaul: Radar stations in remote locations often send digital plot data to Air Route Traffic Control Centers (ARTCC) via legacy serial lines, point-to-point microwave links, or commercial telecommunications networks. In many legacy deployments, these links lack strong cryptographic integrity checks or mutual authentication. An adversary who intercepts this link can inject forged ASTERIX packets representing primary radar tracks.
  • Network Packet Injection: By gaining a foothold inside the Air Navigation Service Provider’s (ANSP) operational network, an attacker can route spoofed UDP/IP packets directly to the operational data ports of the central Radar Data Processing System (RDPS). Because primary radar plots contain minimal identifying telemetry compared to transponder data, a fabricated packet containing realistic range, azimuth, and Doppler attributes will be processed as an uncooperative physical target.

Central System Layer: Radar Data Processing System (RDPS) Manipulation

The Radar Data Processing System (RDPS) correlates data from multiple PSRs, SSRs, and ADS-B receivers into a unified situational picture.

  • Multi-Sensor Fusion Exploitation: The RDPS uses algorithms such as Kalman filters to fuse raw primary returns into continuous tracks. Attackers targeting the RDPS software itself can exploit memory corruption vulnerabilities, malicious software updates, or misconfigured integration APIs to inject synthetic tracks directly into the database.
  • Display Subsystem Spoofing: An adversary can bypass radar sensors entirely by compromising the Controller Working Position (CWP) human-machine interface. Injecting data at the local display client forces ghost aircraft symbols onto the air traffic controller's screen, achieving the operational effect of false primary returns without interacting with any radar hardware.
