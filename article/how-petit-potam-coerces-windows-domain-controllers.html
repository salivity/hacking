How PetitPotam Coerces Windows Domain Controllers

PetitPotam is a post-exploitation technique that forces Windows Domain Controllers to initiate an authentication request to an untrusted external server, allowing attackers to perform severe NTLM relay attacks. By exploiting unauthenticated or low-privileged access to the Microsoft Encrypting File System Remote Protocol (MS-EFSRPC), an attacker can supply a malicious Universal Naming Convention (UNC) path to the target server. The target domain controller immediately attempts to access that path under the context of its computer account (SYSTEM), generating an NTLM authentication challenge that the attacker captures and relays to achieve unauthorized access—frequently culminating in full Active Directory domain compromise.

The Exploitation Mechanism: MS-EFSRPC

The core of the PetitPotam technique relies on the Encrypting File System Remote Protocol (MS-EFSRPC), an RPC interface designed to manage encrypted files stored remotely. By default, Windows systems expose this service over named pipes (such as \pipe\efsrpc, \pipe\lsarpc, or \pipe\samr) accessible via the Server Message Block (SMB) protocol over port 445.

PetitPotam targets functions within the protocol that handle file operations, most notably:

  • EfsRpcOpenFileRaw
  • EfsRpcEncryptFileSrv
  • EfsRpcDecryptFileSrv
  • EfsRpcQueryUsersOnFile

These functions accept a UNC path pointing to the file to be processed. When an attacker connects to the domain controller and invokes one of these functions, they specify an arbitrary UNC path pointing directly to an attacker-controlled server (e.g., \\attacker-ip\share\test.txt).

Crucially, in unpatched configurations, the interface accepts these requests from unauthenticated network users or users with standard, low-privileged domain accounts.

Authentication Coercion

Once the domain controller processes the RPC function call containing the attacker's UNC path, it performs the following steps:

  1. Path Resolution: The domain controller attempts to open the network resource specified in the UNC path.
  2. Context Assumption: Because the MS-EFSRPC service runs inside the Local System context (NT AUTHORITY\SYSTEM), the host uses its machine account credentials (DC_NAME$) to establish the connection.
  3. SMB Negotiation: The domain controller initiates an outbound SMB connection to the attacker's IP address.
  4. NTLM Handshake: The attacker's server prompts the domain controller to authenticate via NTLM. The domain controller responds by initiating an NTLM Type 1 (Negotiate) message, accepts the attacker's Type 2 (Challenge) response, and generates a Type 3 (Authenticate) response containing its encrypted machine credentials.

This sequence forces the target to initiate the connection outward, bypassing traditional inbound firewall restrictions and perimeter defenses.

The Role of NTLM Relaying

PetitPotam itself does not crack the domain controller's machine account password hash. Instead, it serves purely as the authentication coercion component in an NTLM relay attack chain:

  1. Traffic Interception: The attacker sets up a relay listener (such as ntlmrelayx) on their host.
  2. Coercion: The attacker executes PetitPotam against the domain controller, directing the outbound authentication to the relay listener.
  3. Relay to Target Service: As the domain controller authenticates to the attacker, the listener relays the NTLM authentication tokens in real time to another internal network service that accepts NTLM authentication.
  4. Privilege Abuse: A frequent target is Active Directory Certificate Services (ADCS) Web Enrollment endpoints (HTTP). Because HTTP typically lacks NTLM Extended Protection for Authentication (EPA), the relay succeeds.
  5. Domain Takeover: The relay agent uses the domain controller's relayed credentials to request a digital certificate on behalf of the domain controller. Using the issued certificate, the attacker can authenticate via Kerberos Public Key Cryptography for Initial Authentication (PKINIT) to obtain a Kerberos Ticket Granting Ticket (TGT), ultimately executing a DCSync attack to compromise the entire Active Directory domain.

Remediation and Mitigations

Defending against PetitPotam coercion and subsequent relay attacks requires securing both the RPC interfaces and the services accepting NTLM:

  • Install Security Updates: Apply Microsoft patches for CVE-2021-36942, which block unauthenticated calls to the EFSRPC interface.
  • Disable NTLM: Enforce Kerberos-only authentication across the domain where possible.
  • Harden Target Services: Enable Extended Protection for Authentication (EPA) and require HTTPS on ADCS web endpoints.
  • Require SMB Signing: Mandate SMB signing across all domain controllers to block SMB-to-SMB relaying.
  • Block Unneeded RPC Interfaces: Disable the EFS service on domain controllers if it is not explicitly required for administrative workflows.
