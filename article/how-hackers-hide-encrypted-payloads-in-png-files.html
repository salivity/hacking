How Hackers Hide Encrypted Payloads in PNG Files

Steganography allows threat actors to conceal encrypted executable code inside standard PNG images to bypass firewalls, intrusion detection systems, and content filters. Because the PNG format relies on lossless compression, it provides a deterministic medium where modified pixel data and metadata remain intact upon storage and transfer. Attackers utilize several distinct algorithmic methods—including spatial bit manipulation, custom chunk injection, color palette exploitation, and scanline filter evasion—to weave arbitrary binary data seamlessly into the image's binary structure without creating noticeable visual distortion.

Least Significant Bit (LSB) Substitution

The most common technique is Least Significant Bit (LSB) substitution. A standard 24-bit RGB PNG uses 8 bits per channel (Red, Green, Blue) to represent color values ranging from 0 to 255. In a 32-bit RGBA image, an 8-bit Alpha channel is added.

Attackers target the lowest-order bit (Bit 0) of individual color channels. Changing the least significant bit alters a color value by at most 1/256th, which is imperceptible to the human eye.

To embed an encrypted payload:

  1. The payload binary is encrypted (often with AES or RC4) to ensure high entropy, mimicking random noise.
  2. The payload is flattened into a sequential stream of bits.
  3. An algorithm iterates over the image's raw pixel array, replacing the least significant bit of selected bytes with a bit from the payload stream.
  4. To evade statistical steganalysis (such as Chi-square distribution tests), attackers avoid sequential replacement. Instead, they use a pseudo-random number generator (PRNG) seeded with a shared secret key to distribute the payload bits non-contiguously across the image matrix.

Because PNG uses the Deflate algorithm (a combination of LZ77 and Huffman coding) for lossless compression, the modified raw pixel values are preserved perfectly when the file is decompressed by an operating system or browser.

Ancillary and Custom Chunk Injection

A PNG file is structurally composed of discrete blocks called "chunks," each consisting of a length field, a 4-byte chunk type identifier, chunk data, and a Cyclic Redundancy Check (CRC). Standard chunks include IHDR (image header), IDAT (image data), and IEND (image trailer).

Attackers exploit the PNG chunk specification in two primary ways:

  • Abusing Standard Ancillary Chunks: PNG supports optional metadata chunks such as tEXt, zTXt (compressed text), and iTXt. Attackers can store Base64-encoded, encrypted binary payloads inside these metadata fields. Standard image viewers simply ignore unrecognized or extended text metadata.
  • Creating Custom Chunks: Attackers construct custom chunk identifiers (following the PNG specification rule where a lowercase fourth letter indicates an ancillary, copy-safe chunk). Image parsers skip unrecognized chunks that have valid length and CRC headers, but a dedicated malicious loader script can locate the specific chunk identifier, extract the data, decrypt it, and execute it in memory.
  • Trailing Data (EOF Appending): Attackers often append raw, encrypted binaries directly after the IEND chunk. Decoders stop processing the image once the IEND marker is reached, rendering the image normally, while malware stagers seek to the end of the file to recover the appended binary.

Palette Modification (PLTE Chunk Exploitation)

In indexed-color PNG files (color type 3), the image does not define RGB values for each pixel directly. Instead, it defines a color palette in a PLTE chunk containing up to 256 colors, and each pixel references an index within this table.

Attackers manipulate palette-based images using two techniques:

  • Palette Sorting and Permutation: By altering the numerical order of colors in the palette and updating the corresponding pixel indices to match, attackers can encode binary bits into the relative ordering permutations of the palette entries.
  • Color Parity Manipulation: Attackers can subtly modify the least significant bit of the RGB values within the PLTE definition itself, or insert nearly identical color duplicates into the palette to toggle binary states based on which identical palette entry a pixel points to.

Scanline Pre-Filtering Exploitation

Before Deflate compression is applied, PNG passes raw scanlines through predictive delta filters to maximize compression efficiency. The specification defines five filter types for each row of pixels: None (0), Sub (1), Up (2), Average (3), and Paeth (4).

Advanced steganographic malware factors these mathematical filter functions directly into its injection algorithm. By mathematically calculating the inverse of the filter algorithm prior to compression, attackers craft payload bits that survive the filtering step while actively reducing the file size impact or preventing anomalous compression ratios that signature-based security scanners monitor.

Extraction and Execution Routine

Regardless of the embedding method used, the image file alone cannot initiate code execution. Attackers deliver the weaponized PNG alongside, or prior to, a lightweight "stager" or "loader" (often delivered via phishing, macros, or PowerShell scripts).

The loader program loads the PNG into memory, parses the file structure to locate the target bits or chunks, decrypts the extracted byte array using an embedded key, and allocates executable memory (such as via VirtualAlloc on Windows) to execute the newly reconstituted payload directly in RAM.
