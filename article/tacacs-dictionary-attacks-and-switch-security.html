TACACS+ Dictionary Attacks and Switch Security

This article examines how threat actors target the TACACS+ protocol using dictionary attacks to compromise administrative credentials on network switches. It details the underlying cryptographic weaknesses in TACACS+ body encryption, the methodology used to capture and analyze authentication traffic offline, and essential defensive measures required to secure management planes against these attacks.

The TACACS+ Encryption Mechanism and Its Vulnerability

Terminal Access Controller Access-Control System Plus (TACACS+) is widely deployed in enterprise networks to provide centralized Authentication, Authorization, and Accounting (AAA) for network devices. Unlike RADIUS, which only encrypts the password attribute, TACACS+ encrypts the entire payload of the packet following a standard 12-byte unencrypted header.

The vulnerability lies in how this encryption is implemented. TACACS+ uses a proprietary pseudo-random stream cipher based on the MD5 hash function. The key stream is generated by iteratively hashing the session ID, a pre-shared secret key, a version number, and the sequence number. The resulting pseudo-random pad is then XORed with the packet body.

Because MD5 is computationally lightweight and the algorithm generates predictable key streams for known inputs, this obfuscation mechanism does not provide strong cryptographic confidentiality by modern standards.

How Offline Dictionary Attacks Occur

Adversaries do not typically launch online dictionary attacks directly against the network switch or AAA daemon due to account lockout policies and rate limiting. Instead, they leverage the cryptographic design of TACACS+ to perform offline dictionary attacks.

1. Traffic Interception

The adversary must first position themselves to intercept TACACS+ traffic traversing the management network (typically over TCP port 49). This is accomplished through techniques such as:

  • Man-in-the-Middle (MitM) positioning via ARP spoofing or rogue DHCP servers.
  • Compromising an intermediary switch and configuring a Switched Port Analyzer (SPAN) or port mirror.
  • Tapping unsegmented network links where management traffic shares bandwidth with general user traffic.

2. Identifying Known Plaintext

Because the TACACS+ packet header remains unencrypted, an observer can read the session ID, sequence number, flags, and payload length. Furthermore, portions of the packet body follow strict formatting rules defined by the RFC (such as standard authentication start flags or common username prompts). This predictable structure provides known or partially known plaintext.

3. Offline Key Recovery

Once packets containing an authentication exchange are captured, the adversary extracts the ciphertext and unencrypted parameters. Using an offline dictionary attack:

  • The cracking program iterates through wordlists containing candidate shared secret keys.
  • For each candidate key, it computes the MD5 pseudo-random pad according to the TACACS+ specification.
  • The generated pad is XORed against the captured ciphertext.
  • The output is validated against expected structural values (such as standard packet flags or ASCII character ranges).

Because the verification happens entirely offline on the attacker’s local hardware, thousands or millions of key candidates can be evaluated per second without alerting the AAA server or triggering lockouts.

4. Credential Extraction

Once the correct pre-shared key is recovered, the adversary decrypts the entire session payload. This exposes:

  • The administrative username submitted in the START packet.
  • The cleartext password or hash submitted in the CONTINUE packet.
  • Subsequent authorization requests and privileged commands executed during the session.

With these administrative credentials, the adversary can log directly into network switches, reconfigure access control lists, modify routing tables, or establish persistent backdoors.

Defensive Strategies and Countermeasures

Mitigating dictionary attacks against TACACS+ requires addressing both the weak shared-secret reliance and the exposure of network traffic.

  • Transition to TACACS+ over TLS (RFC 8907): Modern implementations support encapsulating TACACS+ inside Transport Layer Security (TLS), replacing the weak MD5-based stream cipher with robust, industry-standard encryption and mutual certificate authentication.
  • Enforce High-Entropy Shared Secrets: If legacy TACACS+ must be used, the pre-shared key should be generated randomly with high entropy (at least 32 characters comprising alphanumeric and special symbols), rendering standard dictionary attacks ineffective.
  • Strict Management Plane Segmentation: Place all switch management interfaces and AAA servers on dedicated, isolated Out-of-Band (OOB) management VLANs. Ensure no user traffic or untrusted access is permitted on these subnets.
  • Dynamic ARP Inspection and Port Security: Implement layer 2 defenses to prevent ARP poisoning and unauthorized device connection, reducing the likelihood of traffic sniffing within the management segment.
