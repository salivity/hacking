How Rogue DHCP Servers Hijack Network Routing

A rogue Dynamic Host Configuration Protocol (DHCP) server is an unauthorized device placed on a local network that intercepts and manipulates client configuration parameters. Because standard DHCP exchanges lack native authentication, an attacker can respond to initial network connection requests faster than the legitimate DHCP infrastructure. By doing so, the rogue server injects malicious routing data—specifically by reassigning the default gateway and primary Domain Name System (DNS) servers—allowing the attacker to stage Man-in-the-Middle (MitM) attacks, monitor unencrypted traffic, and arbitrarily redirect network communications.

The DHCP Exchange and the Race Condition

When a device connects to a local area network (LAN), it negotiates its IP parameters using the four-step DORA process: Discover, Offer, Request, and Acknowledge.

  1. DHCP Discover: The client broadcasts a request across the local broadcast domain to locate an available DHCP server.
  2. DHCP Offer: Any listening DHCP server responds with an offer containing an IP address, subnet mask, default gateway, and DNS servers.
  3. DHCP Request: The client typically accepts the first valid offer it receives and broadcasts a request to lease those specific settings.
  4. DHCP Acknowledge (ACK): The responding server finalizes the lease.

Because the client accepts the first response it encounters, an attacker on the same broadcast domain creates a race condition. By positioning a rogue server that responds marginally faster than the network’s authentic server—or by disabling the real server via a DHCP starvation attack—the rogue server guarantees that the victim accepts its malicious configuration payload.

Pushing Malicious Default Gateways (DHCP Option 3)

The default gateway tells a host where to send traffic destined for any IP address outside its local subnet. In a rogue DHCP deployment, the attacker uses DHCP Option 3 (Router Option) to assign their own machine’s IP address as the client's default gateway.

Once the client commits this configuration:

  • All outbound Internet and cross-subnet packets are directed to the attacker's physical hardware.
  • The attacker enables IP forwarding on their system, silently relaying traffic between the victim and the legitimate router to avoid raising suspicion.
  • With traffic routing directly through the attacker’s network interface, the attacker gains full Man-in-the-Middle (MitM) capabilities, allowing for passive packet sniffing, session hijacking, or selective packet dropping and tampering.

Pushing Malicious DNS Configurations (DHCP Option 6)

DHCP Option 6 specifies the DNS server addresses the client should use to resolve domain names to IP addresses. A rogue server overrides this setting with the IP address of an attacker-controlled DNS server.

Manipulating DNS entries allows the attacker to compromise network routing at the application layer:

  • Targeted DNS Spoofing: When the client requests an IP for an external service, the malicious DNS server returns the IP address of an attacker-hosted credential harvesting page or malware delivery server.
  • Selective Resolution: To maintain stealth, the rogue DNS server forwards legitimate requests for mundane services to a public resolver (like 8.8.8.8) while selectively spoofing high-value targets, such as intranet portals, internal corporate services, or banking domains.
  • Bypassing Encryption Protections: By pairing malicious DNS resolution with tools that enforce SSL stripping or present custom root certificates, attackers can downgrade secure connections or trick users into trusting fraudulent TLS endpoints.

Attack Execution and Network Defenses

To maximize the reach of the attack, attackers often precede a rogue DHCP deployment with a DHCP starvation attack. Tools like yersinia flood the authentic DHCP server with requests using spoofed MAC addresses, exhausting the server's pool of available IP leases. Once the legitimate server is unresponsive, the rogue server becomes the sole responder on the network.

Organizations mitigate rogue DHCP routing attacks primarily through Layer 2 switch security features:

  • DHCP Snooping: Configured on managed network switches, DHCP snooping designates specific switch ports as "trusted" (connected to legitimate DHCP infrastructure) and all other ports as "untrusted." The switch drops any DHCP Offer or ACK messages originating from an untrusted port.
  • Port Security: Restricting the number of MAC addresses permitted on an individual switch port prevents the MAC exhaustion tactics required for DHCP starvation attacks.
  • Static Configurations and 802.1X: Implementing dynamic port-based network access control (802.1X) prevents unauthorized rogue machines from joining the broadcast domain entirely, neutralising the attack vector before configuration exchanges occur.
