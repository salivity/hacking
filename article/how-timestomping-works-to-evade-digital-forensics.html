How Timestomping Works to Evade Digital Forensics

Timestomping is an anti-forensics technique where threat actors alter the metadata timestamps of files—specifically modification, access, creation, and birth (MACB) attributes—to conceal malicious activity from security analysts. By modifying these chronological indicators, attackers cause malicious executables and tools to blend into legitimate operating system directories, breaking forensic timelines and bypassing detection filters that flag recently created or modified files.

The Mechanics of Timestomping

Operating systems rely on file system metadata to track when files are interacted with. In Windows environments using the NTFS file system, timestamps are stored in two primary attributes within the Master File Table (MFT):

  1. $STANDARD_INFORMATION ($SI): Contains the standard MACB timestamps visible to users and common administrative tools via the operating system interface.
  2. $FILE_NAME ($FN): Contains a secondary set of MACB timestamps that are typically updated only by the Windows kernel during specific file operations, such as creating, moving, or renaming a file.

Timestomping generally targets the $STANDARD_INFORMATION attribute. Attackers leverage native operating system Application Programming Interfaces (APIs), such as the Win32 SetFileTime function, to arbitrarily rewrite the creation, last access, and last write times. In Linux and Unix environments, attackers achieve similar results using the utime system call or command-line utilities like touch -r (which references another file’s timestamp) or touch -t (which sets an explicit date and time).

Attack Execution and Techniques

Attackers employ several methods to apply timestomping during an intrusion:

  • Post-Exploitation Frameworks: Tools such as Metasploit's Meterpreter feature built-in modules (e.g., the timestomp command) that automatically copy the timestamps of a known legitimate binary—such as calc.exe or kernel32.dll—onto newly deployed payloads.
  • Living-off-the-Land Scripts: Attackers often execute PowerShell or native shell scripts to programmatically adjust timestamps immediately after downloading or compiling tools onto the victim machine, ensuring minimal time elapses where the file shows an anomalous timestamp.
  • Direct MFT Manipulation: Sophisticated malware may bypass user-mode APIs altogether and write directly to raw disk sectors to modify both $STANDARD_INFORMATION and $FILE_NAME attributes, making detection more difficult.

Impact on Digital Forensics and Incident Response

Forensic investigators reconstruct security incidents by building a unified timeline of events, often referred to as a "super-timeline." Timestomping disrupts this process in several ways:

  • Triage Evasion: Incident responders frequently filter files by the timeframe of the suspected breach (e.g., inspecting all files created in the last 48 hours). A malicious file backdated to 2018 will escape this initial triage.
  • Chronological Disruption: By placing file creation dates prior to related events (such as phishing execution or command-and-control communication), attackers mask the cause-and-effect relationship between attack phases.
  • Mimicking System Files: When deploying persistence mechanisms, such as scheduled tasks or services, placing a backdated binary in C:\Windows\System32 allows it to look indistinguishable from native operating system files during casual inspection.

Forensic Detection of Timestomping

Despite its effectiveness against basic file analysis, timestomping leaves distinct artifacts that forensic examiners exploit to uncover tampering:

  • $SI vs. $FN Discrepancies: Because standard user-mode APIs like SetFileTime only modify the $STANDARD_INFORMATION attribute, a discrepancy often exists between $SI and $FILE_NAME timestamps. If the $SI creation date predates the $FN creation date, timestomping has likely occurred.
  • Sub-Second Precision Analysis: Native Windows file creation mechanisms record timestamps with nanosecond precision. Many automated timestomping tools fail to emulate this granularity, zeroing out sub-second values (e.g., 12:00:00.0000000), which immediately signals manipulation.
  • NTFS Log Tracking: NTFS transactional logs, specifically the $LogFile and the Update Sequence Number (USN) Journal, log changes to the file system as they occur. Even if the metadata on the file itself is rewritten, the USN Journal preserves the real-world time at which the metadata modification record was generated.
