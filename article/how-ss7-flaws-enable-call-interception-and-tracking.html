How SS7 Flaws Enable Call Interception and Tracking

Signaling System 7 (SS7) is an international telecommunications backbone developed in the 1970s to coordinate call routing, billing, and roaming between cellular networks worldwide. Because the protocol was designed during an era when only a handful of state-owned telecom monopolies had access to it, it operates on a model of implicit trust with virtually no built-in cryptographic authentication. Today, attackers who gain access to this legacy signaling network can exploit its core architecture to track physical locations, eavesdrop on phone calls, and intercept SMS-based two-factor authentication codes from anywhere in the world.

The Underlying Vulnerability: A Legacy of Implicit Trust

SS7 functions as the nervous system of modern cellular interconnectivity, facilitating communication between different Mobile Network Operators (MNOs). When a subscriber travels abroad, their home network and the visiting network exchange SS7 packets to verify identity, establish routing, and maintain service continuity.

The primary vulnerability of SS7 is that it treats any message originating from within the signaling network as inherently trustworthy. While acquiring access to the SS7 network once required physical access to carrier switches, modern access can be leased legitimately via third-party aggregators, purchased illicitly on underground forums, or gained by breaching poorly secured regional telcos. Once an attacker establishes an SS7 connection, they can send unauthorized requests disguised as legitimate roaming operations.

How Hackers Track Location via SS7

SS7 location tracking relies on querying databases that track a subscriber's current status and physical tower attachment: the Home Location Register (HLR) and the Visiting Location Register (VLR).

  1. Target Identification: The attacker begins with the victim's standard telephone number (MSISDN). Because SS7 relies on an internal network identifier called the International Mobile Subscriber Identity (IMSI), the attacker sends an SS7 query—often a SendRoutingInfoForSM (SRI-SM) message—to the victim's home carrier.
  2. IMSI Resolution: The home carrier's HLR, assuming the request is a legitimate incoming SMS attempt, replies with the subscriber's IMSI and the address of the MSC (Mobile Switching Center) currently serving the phone.
  3. Pinging the Serving Network: Armed with the IMSI, the attacker issues a ProvideSubscriberInfo (PSI) or AnyTimeInterrogation (ATI) command directly to the visiting MSC.
  4. Extracting Tower Data: The serving MSC responds with operational telemetry, including the Cell Global Identity (CGI). The CGI identifies the precise cell tower handling the target's connection.
  5. Geolocation Mapping: By correlating the CGI against public or proprietary databases of global cell tower coordinates, the attacker determines the user's real-time geographic location, often within a radius of a few hundred meters, without alerting the victim.

How Hackers Intercept Calls and SMS

Intercepting communications requires manipulating how calls and messages are directed, effectively executing a Man-in-the-Middle (MitM) attack over the cellular control plane.

  1. Spoofing Network Registration: An attacker sends an UpdateLocation or InsertSubscriberData (ISD) request to the target's HLR. This message falsely claims that the victim has roamed onto a rogue network switch controlled by the attacker.
  2. Rerouting the Traffic: When an incoming call is placed to the victim, the HLR consults its database and routes the call to the attacker's switch rather than the legitimate carrier.
  3. Silent Man-in-the-Middle: The attacker's system answers the incoming call, initiates a parallel call to the victim's actual phone, bridges the two audio streams together, and records the conversation. Neither the caller nor the recipient detects the divergence because the call connects normally.
  4. SMS Interception: Attackers execute a similar redirection for text messages using spoofed SRI-SM requests. When banks or online services send one-time passwords (OTPs) via SMS, the signaling network sends the payload directly to the attacker's endpoint, facilitating account takeovers and financial theft.

The Challenge of Securing SS7

Securing SS7 remains a persistent global challenge. While modern 4G networks utilize the Diameter protocol and 5G relies on HTTP/2-based Service-Based Architectures (SBA), backward compatibility forces all global telecom networks to maintain SS7 interconnections. Flaws in older generations degrade the security of newer ones, as attackers can force fallbacks to legacy routing protocols.

Defending against SS7 abuse requires mobile network operators to deploy advanced signaling firewalls capable of inspecting message context, filtering unauthorized remote queries, and verifying whether a subscriber is genuinely roaming. For end users, mitigating SS7 exploitation requires adopting end-to-end encrypted messaging applications (such as Signal or WhatsApp) for voice and text, as well as replacing SMS-based authentication with hardware security keys or software-based authenticators.
