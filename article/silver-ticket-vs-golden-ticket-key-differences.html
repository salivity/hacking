Silver Ticket vs Golden Ticket: Key Differences

In Active Directory environments, Kerberos ticket forgery represents one of the most potent post-exploitation techniques used by attackers for lateral movement and persistence. While both Golden and Silver Ticket attacks exploit weaknesses in Kerberos authentication to forge identity claims, they differ fundamentally in their operational scope, the cryptographic material required to forge them, their interaction with Domain Controllers, and their detection footprints. Understanding these distinctions is critical for incident responders and network defenders seeking to identify and mitigate targeted Kerberos-based intrusions.

Targeted Component and Ticket Type

The primary distinction between the two attacks lies in which Kerberos ticket type is forged and which entity validates it:

  • Golden Ticket (Forged TGT): The attacker creates a counterfeit Ticket Granting Ticket (TGT). In Kerberos, a TGT acts as proof of identity and allows a user to request access to any network resource. Because a Golden Ticket mimics a valid TGT, the attacker can present it to the Key Distribution Center (KDC) to request a Ticket Granting Service (TGS) ticket for virtually any service across the entire Active Directory domain.
  • Silver Ticket (Forged TGS): The attacker creates a counterfeit Ticket Granting Service (TGS) ticket directly. A TGS ticket grants access only to a specific service or resource (such as CIFS, LDAP, HTTP, or MSSQL). Consequently, a Silver Ticket confers access exclusively to the target service running on a specific host, rather than domain-wide administrative authority.

Cryptographic Keys Required

To forge a valid Kerberos ticket, an attacker must possess the secret key used to encrypt and sign that specific ticket type:

  • Golden Ticket: Requires the NTLM password hash or AES keys of the krbtgt account. The krbtgt account is the central service account used by the KDC to sign and encrypt all TGTs. Compromising this key requires Domain Admin or equivalent privileges.
  • Silver Ticket: Requires only the password hash (NTLM or AES) of the target service account hosting the service (often a local machine account or a dedicated user service account). Compromising the krbtgt account is unnecessary, meaning an attacker only needs local administrator privileges on the target server or access to that specific service account's credentials.

Interaction with the Domain Controller

Network communication and Domain Controller (DC) interaction vary drastically between the two techniques:

  • Golden Ticket: The attacker presents the forged TGT to the Domain Controller (specifically the KDC) to request a TGS ticket. Although the ticket itself is forged offline, the subsequent exchange creates network traffic destined for the DC.
  • Silver Ticket: The attacker communicates directly with the target application or server, bypassing the Domain Controller entirely. Because the target server decrypts and verifies the TGS ticket using its own local key, it assumes the KDC already validated the request and does not contact the DC for confirmation.

Stealth and Evasion

Because of the architectural differences, Silver Tickets are typically stealthier than Golden Tickets:

  • Golden Ticket Stealth: Easier to detect centrally. The forged TGT generates Kerberos service ticket requests on the Domain Controller. Security monitoring tools analyzing KDC logs can flag anomalies, such as mismatched encryption algorithms, abnormal ticket lifetimes, or accounts requesting tickets without prior authentication events.
  • Silver Ticket Stealth: Extremely difficult to detect through centralized logging. Because the Domain Controller is never contacted, no Kerberos events (such as Event ID 4769) are logged on the DC. Detection relies strictly on local event logs on the target system, where the activity often blends in with standard user access.

Persistence and Remediation

Remediating these attacks requires targeting different layers of the Active Directory infrastructure:

  • Golden Ticket Remediation: Requires resetting the domain's krbtgt account password twice. Because Active Directory stores both the current and previous krbtgt password hashes to prevent immediate service disruption, a single reset does not invalidate existing forged Golden Tickets.
  • Silver Ticket Remediation: Requires identifying the specific compromised service or computer account and resetting its password or machine account secret. Resetting the krbtgt account has zero effect on forged Silver Tickets.
