Active Directory Unconstrained Delegation Attacks

Active Directory unconstrained delegation is a legacy Kerberos feature designed to allow services to impersonate users across multiple back-end resources without re-prompting for credentials. However, this architectural design creates severe vulnerabilities that enable adversaries to harvest Ticket Granting Tickets (TGTs) from compromised hosts. This article examines the security gaps inherent in unconstrained delegation, how attackers manipulate these trust relationships to extract Kerberos tickets, and the mechanisms used to turn delegated systems into enterprise-wide compromise vectors.

The Inherent Flaw in Unconstrained Kerberos Delegation

When an Active Directory computer or service account is configured with unconstrained delegation (the TRUSTED_FOR_DELEGATION userAccountControl flag), any user authenticating to that service sends a copy of their forwardable TGT along with the service ticket.

The application server must hold the TGT to impersonate the user against downstream services. Because Kerberos cannot anticipate which specific back-end servers will be accessed, the Kerberos Key Distribution Center (KDC) provides a fully reusable TGT that is valid for any service across the entire domain.

Memory Storage and Ticket Harvesting

The primary security gap lies in how the operating system handles received TGTs:

  1. Storage in LSASS: When a user connects to a service on an unconstrained delegation host, the forwardable TGT is placed directly into the Local Security Authority Subsystem Service (LSASS) process memory.
  2. Persistence Beyond the Session: The extracted TGT remains cached in memory until it expires (typically 10 hours by default), long after the originating user session terminates.
  3. Local Administrator Extraction: If an attacker gains administrative access to the machine configured with unconstrained delegation, they can dump the memory of the LSASS process using post-exploitation tooling to extract every cached TGT.

Forced Authentication and Lateral Movement

Adversaries do not simply wait for high-privilege users to connect to a compromised host; they actively force privileged accounts to authenticate to it.

Through protocols that allow authentication coercion—such as the MS-RPRN (Print System Remote Protocol / PrinterBug) or MS-EFSR (Encrypting File System Remote Protocol / PetitPotam)—an attacker can trigger a target machine, such as a Domain Controller, to connect back to the unconstrained delegation server.

When the Domain Controller authenticates to the host:

  • The Domain Controller passes its machine account TGT (e.g., DC01$) to the unconstrained delegation host.
  • The machine TGT is written to LSASS memory.
  • The attacker dumps the TGT and uses it to initiate a DCSync attack via the Directory Replication Service Remote Protocol (MS-DRSR), pulling all Active Directory password hashes directly from the domain.

Remediation and Defense Strategies

Eliminating the risks associated with unconstrained delegation requires shifting to modern delegation architectures and applying credential protection controls:

  • Transition to Constrained Delegation: Replace unconstrained delegation with Kerberos Constrained Delegation (KCD) or Resource-Based Constrained Delegation (RBCD), which restrict target services and prevent arbitrary ticket caching.
  • Mark Accounts as Sensitive: Apply the "Account is sensitive and cannot be delegated" attribute to all administrative and high-value user accounts to prevent the KDC from generating forwardable TGTs for them.
  • Use the Protected Users Security Group: Members of this Active Directory security group are automatically blocked from using Kerberos delegation altogether.
  • Audit and Monitor Active Directory: Continuously query Active Directory for objects with the ADS_UF_TRUSTED_FOR_DELEGATION flag to identify and decommission unneeded legacy delegation trust configurations.
