Understanding Process Hollowing Memory Operations

Process hollowing is a code injection technique where an adversary creates a legitimate process in a suspended state, unmaps its executable memory, and replaces it with a malicious payload before resuming execution. This article examines the sequence of low-level memory operations that take place during this technique, detailing the relevant operating system APIs, virtual memory state transitions, and forensic artifacts left behind in system memory.

1. Creation of the Suspended Host Process

The technique begins with the creation of a benign target process, often a trusted system utility such as svchost.exe or explorer.exe. This is initiated via standard process creation interfaces, such as the Win32 CreateProcess API, using the CREATE_SUSPENDED flag.

At the operating system level, this operation:

  • Allocates an initial Virtual Address Space (VAS) for the new process.
  • Loads the primary image and associated subsystem dependencies (such as ntdll.dll).
  • Maps the initial thread execution structures, including the Process Environment Block (PEB) and the Thread Execution Block (TEB).
  • Suspends the primary thread before it reaches the entry point, preventing the legitimate code from executing while maintaining a valid process handle for the injector.

2. Memory Unmapping (Hollowing)

Once the handle to the suspended process is acquired, the injector deallocates or unmaps the legitimate executable code from the target's address space. This is typically achieved using the native system routine NtUnmapViewOfSection or ZwUnmapViewOfSection.

Key memory changes during this stage include:

  • The base address where the original executable image was loaded (often referenced via the PEB's ImageBaseAddress) is cleared.
  • The Virtual Memory Manager (VMM) marks the associated virtual pages as free or invalid.
  • The thread context remains intact, but the instruction pointer points to an entry point that no longer contains valid executable code.

3. Memory Allocation and Protection Setup

The injecting process must allocate a new region of virtual memory within the target process to host the malicious Portable Executable (PE). This is performed using VirtualAllocEx.

Low-level operations involved:

  • Reservation and Commitment: The injector requests a contiguous memory block of sufficient size to accommodate the payload's headers and sections (MEM_COMMIT | MEM_RESERVE).
  • Base Address Selection: If possible, the memory is allocated at the payload's preferred base address. If that address is unavailable, dynamic relocation entries within the payload must be processed.
  • Page Permissions: Initially, the memory is often allocated with PAGE_EXECUTE_READWRITE (RWX) permissions to allow both writing the payload and subsequent execution, or configured with discrete permissions (PAGE_READWRITE followed by PAGE_EXECUTE_READ) to avoid triggering behavioral heuristics.

4. Writing Headers and Sections

The payload is written into the hollowed process using WriteProcessMemory. Rather than a simple file copy, the PE structure must be manually mapped as an OS loader would:

  • PE Headers: The DOS header, PE signature, file header, and optional header are written to the allocated base address.
  • Section Alignment: Each section (such as .text, .data, and .rdata) is copied according to its relative virtual address (RVA) and virtual size, rather than raw disk offsets.
  • Relocation and Import Resolution: If the allocated base address differs from the payload's preferred base, relocation tables are applied to adjust internal memory addresses.

5. Thread Context Modification

To divert execution to the injected code, the primary thread's execution context must be updated. This is handled via GetThreadContext and SetThreadContext.

  • The injector retrieves the current register states contained within the CONTEXT structure.
  • On x86 architectures, the EAX register is updated to point to the entry point of the new payload. On x64 architectures, the RCX or RIP register is updated.
  • If the image base has moved, the PEB's ImageBaseAddress field within the target process is updated via WriteProcessMemory so that APIs querying the process image location reflect the new address.

6. Thread Resumption

Execution is triggered by calling ResumeThread. The OS kernel decrements the thread's suspend count to zero, placing the primary thread into the scheduler queue. The CPU restores register values from the modified CONTEXT structure, and execution begins directly at the new payload's entry point inside what appears to be a legitimate host process.

Detection and Behavioral Indicators

Process hollowing introduces specific low-level anomalies that monitoring systems and memory analysis tools detect:

  • Memory-Disk Mismatches: Discrepancies between the executable mapped in memory and the file on disk referenced by the process path.
  • Unusual Page Permissions: Executable regions mapped as private memory (MEM_PRIVATE) rather than mapped image memory (MEM_IMAGE).
  • PEB Discrepancies: Inconsistencies between the path in the PEB loader data table (Ldr) and the actual loaded modules.
  • API Call Sequences: Suspicious chains of cross-process memory modification calls (NtUnmapViewOfSection, VirtualAllocEx, WriteProcessMemory, SetThreadContext) originating from unrelated parent processes.
