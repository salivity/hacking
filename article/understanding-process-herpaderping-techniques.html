Understanding Process Herpaderping Techniques

Process Herpaderping is an evasion technique that manipulates how Windows handles executable file mappings and process creation callbacks to conceal malicious code from security products. By altering the source file on disk after creating an execution section but before the process begins execution, the technique creates a discrepancy between what is executed in memory and what security scanners observe on disk. This article explains the underlying file mapping mechanics, the timing of security checks, and how defenders identify the activity.

The Core Concept of Process Herpaderping

Traditional security solutions often rely on kernel callbacks, specifically PsSetCreateProcessNotifyRoutineEx, to scan binaries at process creation time. When this routine triggers, security software receives the process identifier and inspects the backing file on disk to determine whether the executable is benign.

Process Herpaderping exploits the relationship between the Windows Cache Manager, the underlying file handle, and the memory section object (SEC_IMAGE) to manipulate this inspection process.

Step-by-Step File Mapping Mechanics

The technique relies on a specific sequence of system calls that alters the disk contents while preserving the executable code in memory:

  1. File Creation and Payload Delivery:
    The target binary is initially written to a file on disk using standard file operations. This file contains the actual code intended for execution.

  2. Image Section Creation (NtCreateSection):
    The program creates a section object from the file with the SEC_IMAGE flag. In Windows, an image section parses the Portable Executable (PE) headers and maps the sections into virtual memory according to their alignment requirements. At this point, the executable data resides in memory backed by the file's current state.

  3. Disk Modification (The "Herpaderp"):
    Before creating a process or thread, the file handle remains open with write permissions. The actor overwrites the original executable on disk with benign data, garbage bytes, or a different valid binary. Because the image section has already been instantiated in memory, the operating system retains the originally mapped code for execution purposes, but the raw file on disk no longer contains the original payload.

  4. Process Creation (NtCreateProcessEx):
    A process object is created referencing the previously created section object. The process now possesses an address space containing the original payload.

  5. Thread Creation and Notification Trigger:
    When the initial thread is created using NtCreateThreadEx, the Windows kernel invokes registered PsSetCreateProcessNotifyRoutineEx callbacks. Security tools that inspect the backing file associated with the process read the overwritten contents on disk rather than the original executable code.

Discrepancies Between File Cache and Memory

The technique relies on how the Windows kernel manages file handles and section objects:

  • Section Persistence: Once a section is created with SEC_IMAGE, changes written to the file handle do not immediately overwrite the mapped executable pages unless explicitly flushed or re-mapped.
  • Callback Timing: Security drivers typically inspect the file path reported during the process creation callback. Because the file on disk was modified before this callback occurs, static file analysis yields the altered or benign bytes instead of the malicious binary.

Detection and Defensive Countermeasures

While Process Herpaderping evades simple on-disk file checks at process startup, it leaves distinctive forensic and behavioral indicators:

  • Header and Disk Discrepancies: Endpoint Detection and Response (EDR) agents can compare the PE headers and contents in the virtual address space with the corresponding bytes on disk. A mismatch between the memory-mapped image and the raw file indicates potential tampering.
  • High-Entropy or Suspicious Write Sequences: Monitoring for patterns where an executable file is written, mapped as an image section, modified immediately afterward, and then launched as a process provides high-fidelity behavioral detection.
  • Mini-Filter Driver Monitoring: File system mini-filter drivers can track file write operations occurring on files that already have open SEC_IMAGE section handles.
