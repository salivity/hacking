Understanding Rogue IPv6 Router Advertisement Attacks

Rogue IPv6 Router Advertisement (RA) attacks allow an attacker to intercept network traffic on predominantly IPv4 networks by exploiting default operating system configurations that prioritize IPv6 connectivity. Even when an organization has not intentionally deployed IPv6, modern endpoints typically have dual-stack networking enabled by default. By broadcasting spoofed Router Advertisements, an attacker can designate their machine as a default gateway and DNS server, enabling traffic redirection and interception without altering the existing IPv4 configuration.

The Dual-Stack Vulnerability Mechanism

Most modern operating systems (including Windows, macOS, and Linux) ship with dual-stack networking enabled out of the box. According to standard address selection algorithms (such as RFC 6724), operating systems generally prefer IPv6 connectivity over IPv4 when both are available.

In a standard IPv4 network, IPv6 routing may be left unmanaged. Endpoints continuously listen for IPv6 control messages, specifically Stateless Address Autoconfiguration (SLAAC) messages defined in the Neighbor Discovery Protocol (NDP). Under SLAAC, routers periodically send multicast Router Advertisements to announce prefixes, default gateways, and configuration parameters to local nodes.

How Interception Occurs

  1. Broadcasting Rogue Router Advertisements
    An attacker situated on the local network segment transmits unsolicited IPv6 Router Advertisement packets (ICMPv6 Type 134) to the all-nodes multicast address (ff02::1). These advertisements declare the attacker's system as an authoritative local router offering a valid global or unique-local IPv6 prefix.

  2. Endpoint Address Configuration
    Target endpoints receive the rogue RA and automatically generate IPv6 addresses corresponding to the advertised prefix. Because the RA designates the attacker’s link-local address as the default router, the victims update their internal routing tables to route all outbound IPv6 traffic through the attacker.

  3. DNS Redirection via RDNSS or DHCPv6
    Rogue RAs can include Recursive DNS Server (RDNSS) options (RFC 8106), or they can set the "Managed" (M) flag, instructing clients to obtain configuration details via DHCPv6. In either case, the attacker advertises their own machine as the primary DNS server. Because clients prefer IPv6 DNS servers over configured IPv4 DNS servers, subsequent DNS queries are sent directly to the attacker.

  4. Traffic Interception and Relaying
    When a user attempts to access a network resource (such as an internal domain or external website), the client issues a DNS request to the rogue IPv6 DNS server. The attacker can respond with custom IPv6 addresses under their control or proxy the connection to the legitimate destination while capturing sensitive traffic, authentication requests, or session data.

Mitigation Strategies

Securing networks against rogue Router Advertisements requires implementing defensive controls at both the switch and host levels:

  • IPv6 RA Guard: Enable RA Guard (RFC 6105) on network switches. This feature inspects ICMPv6 traffic and drops unauthorized Router Advertisement packets arriving on access ports where only hosts—not legitimate routers—reside.
  • DHCPv6 Snooping: Implement switch-level DHCPv6 snooping to ensure that only authorized DHCPv6 servers can allocate IP parameters to clients.
  • Host-Level Configuration: If IPv6 is not actively supported or needed within an enterprise environment, disable IPv6 bindings on network interfaces across endpoints via group policy or endpoint configuration management.
  • Network Segmentation and Monitoring: Segment local broadcast domains to restrict the reach of multicast packets and deploy intrusion detection signatures capable of identifying anomalous ICMPv6 traffic patterns.
