How BloodHound Uses Graph Theory in Active Directory

BloodHound revolutionizes Active Directory (AD) security by leveraging graph theory to reveal unintended, indirect privilege escalation paths that are practically impossible to identify through traditional administrative audits. By mapping Active Directory identities and permissions as an interconnected graph, BloodHound enables both penetration testers and defenders to visualize complex relationship chains. This article explains how BloodHound models AD data using nodes and edges, applies shortest-path algorithms to discover attack vectors, and uncovers hidden administrative access across enterprise networks.

Active Directory as a Graph: Nodes and Edges

In graph theory, a graph is composed of nodes (vertices) connected by edges (lines). BloodHound, powered by the Neo4j graph database, maps Active Directory by translating directory components into these fundamental elements:

  • Nodes: These represent the entities within an Active Directory environment. Common node types include Users, Groups, Computers, Domains, Organizational Units (OUs), and Group Policy Objects (GPOs).
  • Edges: These represent relationships, access rights, or operational states between nodes. Examples include MemberOf (group membership), AdminTo (local administrator privileges), HasSession (an active user session on a machine), and GenericAll (full control over an object).

In a default Active Directory installation, relationships appear fragmented across thousands of Access Control Lists (ACLs) and registry permissions. BloodHound ingests this raw data via collectors (such as SharpHound) and organizes it into a single, queryable directed graph where edges possess direction, pointing from the entity holding the right to the target entity.

Uncovering Transitive and Indirect Paths

The primary challenge in Active Directory security is the compounding effect of transitive trust. An attacker rarely finds a single misconfiguration that directly grants Domain Admin status. Instead, privilege escalation typically relies on chaining several minor, seemingly benign permissions together.

A standard query might reveal that a low-privileged user belongs to a helpdesk group. That helpdesk group may not have administrative rights on the domain controller, but graph analysis can instantly reveal a multi-step chain:

  1. User A is a member of Group B (MemberOf).
  2. Group B has local administrator rights on Workstation C (AdminTo).
  3. A privileged user, Admin D, has an active logon session on Workstation C (HasSession).
  4. Gaining control of Workstation C allows credential dumping from memory to compromise Admin D.
  5. Admin D has explicit reset-password rights over a Domain Admin account (ForceChangePassword).

To a human administrator viewing static property pages in Active Directory Users and Computers (ADUC), these relationships are completely invisible. In a directed graph, this sequence is merely a connected path of five nodes and four edges.

Algorithmic Pathfinding via Neo4j

BloodHound uses graph search algorithms—primarily variations of Dijkstra’s Algorithm and Breadth-First Search (BFS)—to calculate the shortest path between any compromised node and a designated high-value target (such as the Domain Admins group or Tier-0 assets).

When a query is executed, the graph engine navigates the edges from the starting node outwards. Because graph traversal scales based on the number of connections rather than the total size of the database, the engine can evaluate millions of potential permission chains in milliseconds. The query output highlights the exact sequence of edges the attacker must traverse to achieve their objective, stripping away all irrelevant network noise.

Mapping Complex ACL and Object Abuse Vectors

Beyond simple group memberships and local administrative rights, BloodHound models low-level Active Directory discretionary access control lists (DACLs). Many of the most severe privilege escalation paths involve object manipulation edges, including:

  • WriteDacl: The ability to modify the security permissions of a target object, allowing the attacker to grant themselves full control.
  • WriteOwner: The right to assume ownership of an object, which subsequently allows rewriting the object's DACL.
  • AddMember: The right to add arbitrary users or computers to a privileged group.
  • GenericWrite: The ability to update any attribute of an object, such as modifying a script path associated with a user or machine account.

Because these permissions are often delegated granularly across OUs over years of IT operations, organizations accumulate "permission debt." BloodHound synthesizes these granular permissions into distinct directed edges, demonstrating how a lower-tier account can hijack higher-tier objects step by step.

Transforming Active Directory Assessment

By applying graph theory to identity management, BloodHound transforms Active Directory analysis from a static inspection of individual permissions into a dynamic evaluation of structural relationships. Attackers utilize this capability to compute the path of least resistance to full domain compromise, while defenders use the exact same graph data to locate "choke points"—critical edges that, if removed, break multiple attack paths simultaneously.
