How Flush+Reload Attacks Steal Cryptographic Keys

In multi-tenant cloud environments, co-located virtual machines frequently share the underlying physical CPU hardware, opening the door to microarchitectural side-channel exploits. Cache-timing attacks, most notably the Flush+Reload technique, exploit shared CPU caches to infer sensitive operations occurring within an isolated victim machine. By measuring the precise time required to access shared memory lines, an attacker can determine whether a victim accessed specific code or data, allowing them to reconstruct cryptographic keys bit by bit without ever bypassing the hypervisor's memory isolation boundaries.

The Underlying Shared Architecture

Virtual machines running on the same physical host share hardware resources, including the CPU's Last-Level Cache (LLC) and system memory. To optimize memory efficiency, hypervisors and operating systems often employ memory deduplication (such as Kernel Samepage Merging). When multiple virtual machines run identical operating systems or load the same shared cryptographic libraries (such as OpenSSL), the hypervisor maps those identical memory pages to the same physical memory frames. Even if the VMs have isolated virtual address spaces, they share the physical lines within the inclusive LLC.

The Mechanics of Flush+Reload

The Flush+Reload attack is a high-resolution, low-noise cache side-channel technique that operates in three distinct phases:

  1. Flush: The attacker executes the unprivileged clflush instruction on a specific virtual memory address that maps to a shared physical address. This instruction evicts the target memory line from all levels of the CPU cache hierarchy across all processor cores.
  2. Wait: The attacker halts execution for a predetermined interval, allowing the victim virtual machine to execute its workload. During this time, if the victim executes a function or accesses data located on the flushed memory line, the CPU pulls that line back into the cache.
  3. Reload: The attacker re-accesses (reloads) the target memory line while measuring the access latency using high-precision CPU timing instructions like rdtsc.

If the reload duration is short, a cache hit occurred, proving the victim accessed the target line during the wait interval. If the reload takes significantly longer, a cache miss occurred, indicating the victim did not access that specific line.

Recovering Cryptographic Keys

Cryptographic algorithms historically relied on key-dependent branching or memory access patterns. An attacker can correlate the observed cache hits and misses directly to private key operations:

  • Key-Dependent Control Flow: In asymmetric algorithms like naive RSA implementations using the square-and-multiply method, the algorithm executes a "multiply" function only if a specific bit of the private exponent is 1. By monitoring the memory line containing the multiply subroutine, the attacker records a cache hit whenever a 1 is processed and a cache miss when a 0 is processed, reconstructing the key sequentially.
  • Key-Dependent Table Lookups: Symmetric ciphers like AES traditionally utilized precomputed lookup tables (T-tables) to perform byte substitutions. Because the table index depends directly on the secret key mixed with the plaintext, monitoring which cache lines of the lookup table are loaded reveals the underlying key state.

Mitigation Strategies

Mitigating Flush+Reload attacks requires defenses at multiple levels:

  • Constant-Time Cryptography: Modern cryptographic libraries use constant-time algorithms that eliminate secret-dependent branches and memory lookups, ensuring that access patterns remain identical regardless of key values.
  • Disabling Memory Deduplication: Hypervisors can disable cross-VM page sharing, preventing an attacker from mapping their own virtual memory to the physical cache lines used by other tenants.
  • Hardware Partitioning: Modern processors offer features like Cache Allocation Technology (CAT), allowing hypervisors to assign isolated sections of the LLC to specific virtual machines.
